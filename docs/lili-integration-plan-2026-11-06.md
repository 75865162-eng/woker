## 目标与当前证据

目标：由本仓库同一个 Next.js 应用直接提供 `/lili` 页面与接口，使用主系统登录、组织、工作区及服务端权限，不再依赖本地 43123 代理服务。

- 主应用 `next.config.ts` 目前把开发模式 `/lili/:path*` 转到 `127.0.0.1:43123`；根 `middleware.ts` 对该前缀放行。当前 43123 无监听，3017 日志出现对应 ECONNREFUSED。
- 来源目录 `/Users/chenjieliang/Documents/lili`，当前是无 Git 历史的独立源码包。历史来源版本见 `docs/lili-local-routing.md`，不能据此认定当前所有文件仍与上游一致。
- 实际枚举：18 个 `page.tsx`、22 个 `api/**/route.ts`，另有 3 个 `v2/**/route.ts` 内容/帮助端点；21 个 Prisma 模型。两个 layout 不计入页面数。
- `COVERAGE.md` 声明 107 工具、116 技能、12 工作流、5 课程定义；实施时以文件实际解析和校验结果为准。
- 原 `v2/layout.tsx` 读全局 `AppSetting(id=default)`；原 middleware 仅检查 `dby_session` 是否存在，不能直接用于主系统。
- 原 `tool-config/store.ts` 会按进程目录读写 `.env.local` 与 `.secrets/tool-config.json`，不适用于主系统多人隔离。
- 原 Sellfox adapter 可通过 `SELLFOX_DATABASE_URL` 直连独立库；不原样搬入主系统。
- 主系统已有 `requireApiPermission`、AppShell、Agent 平台、Amazon/Ads/Sellfox 服务和组织/工作区配置边界，应优先复用。

## 拟批准的代码实施范围

### 1. 原生页面与目录内容

- 在 `src/app/lili/` 提供开始、技能、案例、课程、工具、工作流及详情/实验页面，保留 `/lili/v2/*` 已有书签；`/lili` 进入开始页。
- 页面组件与纯函数放到 `src/components/lili/`、`src/lib/lili/`；受审查的工具/技能/课程/工作流定义放到 `src/data/lili/`。不复制 node_modules、构建产物、环境文件、上传文件、私密配置或业务数据库。
- 定义内容从受版本控制的目录读取，不为展示目录依赖 seed 或独立 Lili 数据库。不将整份目录加入主系统所有页面的客户端包。
- 样式限制在 Lili 模块，复用主系统 AppShell、字体和组件，避免原全局 CSS 影响现有页面。
- 工具配置、团队、设置、审批、工作流状态、充值等原入口逐一登记去向：可复用能力进入主系统相应界面；没有等价能力时保留可见入口及明确状态，不伪造积分、支付、邀请或成功结果。不得以缺执行器为由静默移除功能入口。

### 2. 统一登录、权限与接口

- 原生路由可用后删除开发 rewrite 和 `/lili` 认证放行。采用主系统会话，不搬入 Lili 沙盒登录或独立登出实现。
- `/lili` 目录默认纳入现有 `agents:view`；创建/执行复用对应动作权限。设置、团队等页面必须遵守各自 `settings`、`accounts` 权限，不能仅凭 agents 权限放行。
- 采用 `/api/lili/*` 专用接口命名空间，逐个端点校验身份、权限和组织/工作区范围；保留旧 `/lili/api/*` 调用的站内兼容策略，但不向外部进程转发。业务工具继续遵守其原有店铺/站点/角色授权。
- 不把 Lili 的 MCP 目录当成主系统 `/api/mcp/amazon` 凭证授权，不扩大个人 MCP 的范围。

### 3. 数据与执行边界

- 不原样复制 21 个模型，不新增另一份 Store/Product/Campaign/Approval 事实源。商品继续以 ProductRecord 为事实源，Amazon、Ads、Sellfox 使用主系统已有只读查询和明确授权范围。
- 对每个工具建立“定义、已实现 adapter、所需权限、输入 schema、未实现原因”映射。只有字段与授权语义已核实的工具才可调用现有 service；其他保留明确未实现返回，不生成 mock 业务结果。
- 工作流只接既有 Agent 执行/审批/草稿边界；未接入执行器继续明确不可执行。外部写入不得由本次合并自动启用。
- 连接配置 UI 接入主系统已有用户/组织/工作区配置接口；不在运行时写 `.env.local` 或全局 secrets 文件。没有可安全复用的 provider 持久化边界时，列出设计和待办，不自行引入共享明文存储。
- 如盘点后必须新增持久化模型、改变配置加密机制或 API 契约，先补充具体 schema/diff、兼容与回滚方案，再请求确认；本方案不授权这些额外变更。
- 旧 Lili 数据、私密配置、历史执行记录和凭证不自动迁移；如用户需要保留，另提来源、目标、字段映射、dry-run 与审批方案。

## 影响、性能与回滚

- 影响范围：主系统 `/lili` 路由、认证 middleware 中该前缀、权限路径映射、导航入口、新增模块及相关文档。现有 Amazon Ads 等未提交改动保持原样，不纳入本次提交或同步，除非另行明确范围。
- 性能风险：目录文本和工作流定义会增加构建输入与 Lili 页面资源；采用服务端按需读取、详情按需加载，避免首页全量载入技能正文。合并后 Lili 共用 web 进程资源，禁止增加启动时 seed、全量查询、后台轮询或自动执行任务。
- 代码回滚：按本次文件清单逆向撤销新增模块和集成 diff，保留其他工作区改动；旧独立源码保留。恢复旧代理只能恢复旧结构，仍需单独批准并启动独立服务，不能称作已恢复可用。
- 本阶段不执行真实数据库迁移、数据导入、配置写入、真实外部 API、服务启停、Git commit/push 或服务器发布。
