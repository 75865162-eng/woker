# 报告 Worker 前置：任务路由隔离交付

日期：2026-11-06。对应 T08 的结构兼容子项，不代表 T08–T11 整体完成。仅本地代码与隔离 fixture 验证；无真实 Amazon 请求、配置写入、持久数据库迁移、提交推送或部署。

## 本轮代码

- `src/lib/amazon-ads/task-routing.ts`：集中定义已有结构触发来源、阶段、无报告日期及无 ReportRequest/Version 关联的判断。保留默认 `schedule` 与原结构 checkpoint 索引；未知触发来源/阶段不猜测为结构。
- `sync-scheduler.ts`：过期 lease 恢复和到期补投递只选择结构任务；恢复事务再次复核路由条件。不能恢复报告任务并错误写入 `entities` 状态。
- `sync-processor.ts`：读取任务及领取事务均检查结构路由，误投递的报告或未知任务在凭证刷新/transport 前返回。
- `sync-service.ts`：重试最新失败任务前核对类型，拒绝将报告任务改成 `manual-retry` 或重置其预算。暂停计划仍取消其中活动任务；取消/暂停仅在实际涉及结构任务时更新结构 freshness，保留报告请求、预算与证据。

没有新增 Schema、迁移、队列、定时入口、运行配置或 API 参数。没有启用报告正式采集。报告运行代码的并行修改不作为本交付的已完成成果。

## 剩余与回滚

正式报告合同、下载目标规则、报告队列完整恢复/截止/预算语义及 RT01–RT10 故障验收仍按原任务清单落实。本轮只消除结构路径接管报告的风险，不声明报告常规 Worker 已完成。

路由 SQL 增加关联存在性过滤；未做生产规模 P95 benchmark，不据此承诺性能指标，也不引入新索引或缓存。未知历史任务保留原状态供审查，不自动转换、删除或执行。

回滚仅恢复上述筛选/领取/控制代码与定向测试，移除新增 helper；不删除任务、事实、请求或文件。移除隔离会重新暴露误路由风险，正式报告接线前不得绕过该边界。
