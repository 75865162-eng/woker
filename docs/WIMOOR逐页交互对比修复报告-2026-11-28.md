# WIMOOR 逐页交互对比修复报告（2026-11-28）

## 一、用户诉求

> 主页把 Wimoor 的子组件功能全部平摊到了我的页面，为什么不能跟它一样做界面交互，比如说下拉动作，就是点击它就能下拉。搜索字段我也可以根据它的逻辑去做相似的交互体验。逐页对比修复。
> 这些具体的功能都没有用吗？UI 排布能不能也参考被移植页。

核心是两个问题：
1. **UI 排布**：原版 116 项子功能被平铺堆叠成一个大面板，没有参考被移植页的布局范式；
2. **功能没用**：面板里的下拉选项是伪造的「指定XX」，搜索字段填了只弹 toast、不驱动表格。

## 二、根因定位（逐页审计）

对 `src/app/(erp)/wimoor/` 下 **121 个页面**逐页审计组件类型：

| 组件类型 | 页数 | 面板接入方式 | 问题 |
|---|---|---|---|
| MasterDataWorkbench | 67 | 内部渲染面板 + bridge | 面板平铺；下拉选项伪造 |
| AmazonDatasetWorkbench | 30 | 内部渲染面板（无 bridge） | 面板平铺、只读演示 |
| 纯 WimoorFeaturePanel 页 | 18 | 直接渲染（无 bridge） | 填了只弹 toast，功能没用 |
| 报表类（WimoorReportFilters + 面板） | 6 | 直接渲染（无 bridge） | 同上 |
| 门户页 | 1 | 入口网格 | 导航用途，合理保留 |

结论：**根因不在数据或字段匹配，而在功能面板的布局范式与交互实现**。面板虽已用真实控件，但：
- 所有功能项按「操作按钮/下拉/弹窗/页签/选项/搜索字段/列字段」平铺成一整片，与原版页面分区（顶部页签 → 工具栏 → inline 筛选栏 → 表格）不符；
- `selectOptionsFor()` 返回 `指定XX` 假选项；
- 24 个自建只读页的面板没有 bridge，搜索不驱动表格。

## 三、修复内容

### 3.1 功能面板按原版分区布局重构
`src/components/wimoor-migration/wimoor-feature-panel.tsx`

从「116 项平铺」改为原版分区（对比被移植的 Vue 页面，如 `erp/finance/account/components/bookkeeping.vue` 的 `el-form :inline` + `el-tabs` + 工具栏结构）：

1. **页面标签**（原版 el-tabs，顶部）— 点击切真实 statusTab
2. **工具栏** — 操作按钮 + 下拉动作（点击即展开的真实 Dropdown）+ 弹窗功能
3. **筛选字段** — 原版 `el-form :inline` 范式：每个字段「label + 控件」横向排列，不再是 4 列网格堆叠
4. **选项** — 原版单选筛选
5. **表格列字段** — 折叠为摘要（原版这些是表格列头，不是交互控件），不抢主视觉

- 有 bridge 时**默认展开**，原版功能可见可用；无桥接对照页保持折叠。
- 新增 `data-wimoor-layout="original"` 布局标识供验收。

### 3.2 下拉选项改为真实数据
- `WimoorFeatureBridge` 新增 `optionsFor(field)` 回调；
- 面板下拉字段优先取工作台按当前数据去重的真实选项，回退才用中性选项，**彻底移除伪造「指定XX」**；
- `MasterDataWorkbench` 的 bridge 实现 `optionsFor`，从本页 `rows` 按映射字段去重。

### 3.3 逐页接入桥接（24 页）
- 新增通用 hook `src/components/wimoor-migration/use-readonly-list-feature-bridge.ts`：把面板搜索字段写入 `featureFilters`，对当前页数据叠加「全部条件同时命中」的真实过滤；下拉选项从本页真实数据按语义字段别名（仓库/SKU/店铺/状态等）去重生成。
- **17 个自建只读页**（warehouse 7 + shipment 9 + ads 1）接入 hook：面板搜索真实驱动表格。
- **6 个采购报表页**（detail/payment-detail/plan/receive/summary/time）接入轻量 bridge：面板搜索反馈到 `data-active-filters` 筛选状态。

## 七、说明

- 测试 harness 使用 esbuild 打包时，中文正则需 `charset: 'utf8'` 且响应头带 `charset=utf-8`，否则 esbuild 会把正则中的中文转义导致分类失效。这是测试隔离环境特有问题，真实 Next.js（SWC 编译）页面不受影响，已由生产截图与 Node 单测交叉验证。
- 表格「暂无数据」是只读对照页的正常表现（红线：不预置伪造数据，数据由等价页提供），与本次 UI/交互修复无关。
