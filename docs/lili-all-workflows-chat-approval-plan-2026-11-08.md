# Lili 全流程单次对话审批方案（待批准）

## 用户目标

Lili 的每个具体任务在 Codex 对话中审阅方案并批准一次，后续在该方案范围内连续执行；不得要求用户返回浏览器点击审批。一次批准不是所有未来任务的无限授权。已有付费研究授权沿用，不要求重复批准。用户要求的选方向、确认最终结论属于业务决定，仍在对话中询问。

## 已核实的现状

当前目录包含12个模板：周一经营例会、广告止血、销量下滑全链路诊断、新品从上架到开广告、从选品到开品文档、竞品全拆解、补货到发货一条龙、利润体检、大促备战、老品清退、退货攻坚、月度经营报告。

src/lib/lili/catalog.ts 统一生成技能提示，工作流模板来自 workflows-zh/en.json。模板是定义，不等于已接入的执行能力。src/lib/lili/tool-execution.ts 对未映射工具返回501；src/lib/lili/api.ts 对独立审批、工作流等未映射操作返回 lili_operation_not_mapped。不得把这些接口改成假成功。

开品研究已接入 research_confirm 对话确认及付费研究保存授权。ERP 已接入数据读取；data_sync_start 只创建真实变更申请，未通过该工具审批或执行。不同执行域必须复用各自的权限、审批和事实源，不能用研究授权绕过。

## 拟实施范围

1. 建立全 Lili 共用的任务审批约定，覆盖技能和12个工作流的中英文提示、MCP说明及错误/下一步提示。默认以 Codex 对话为审批渠道；网页只供可选查看。
2. 每个可执行任务先形成可审阅清单：组织/工作区/账号、目标对象、动作、参数、付费调用上限、影响和回滚。人类批准后，持久保存清单指纹、版本、明确回复、操作者和时间。任务内相同授权范围不再重复审批；对象、动作或限额超出原方案时，仅在对话中询问新增部分。保留既有权限、租约/CAS、幂等和费用账本，不通过通用任意工具/SQL执行器放行。
3. 开品研究保留现有能力并接入统一约定。针对其他已经接通的执行域，逐个用原有受控服务接入对话确认，不把未批准的操作混入同一任务。同步申请复用原变更申请的审批与应用接口，不绕过服务端校验。
4. 未映射的广告写入、上架、货件等步骤在对话中明确返回“执行器未接入”，保留可生成的分析/草稿，不把用户赶到网页，不虚报已执行。所有未接入项列出清单；本方案不等于授权凭空实现全部Amazon供应商写接口。
5. 当前已授权的两条 Lili 连接按实际所需增加最小工具授权并记录审计；不自动扩权其他用户、组织或工作区，不复制Token，不改变全系统审批。

## 验证计划

按流程覆盖只读直达、首次聊天批准、后续不重复批准、明确拒绝、版本过期/参数变化、重入不重复发送、异常费用、无权限/跨工作区拒绝及未接入返回真实状态。运行相关隔离测试、check:fast及必要浏览器兼容回归；准备合码/上线前另跑完整check。真实外部写入不作为自动测试，无对应具体执行方案批准时不启动真实任务。原生MCP检查工具发现、认证、授权及下一步提示。

## 回滚及发布边界

保持旧网页审批可选使用。新增任务授权采用可识别版本，关闭新增策略及撤销新增工具授权即可退回旧流程；保留审批、调用、费用和结果历史。已发出的外部动作不能靠回滚代码撤销，需用对应业务域的逆向草稿。若现有表/JSON边界不足，先提交具体数据模型增量，不隐式迁移。无服务器发布、重启、迁移、commit或push；这些仍遵守原审批及全改动区盘点规则。

本方案涉及共享权限与多个业务模块，依据仓库AGENTS.md的“全局影响预告”，等待用户针对以上范围明确确认后修改实现。当前仅只读盘点并生成方案，尚未把全部流程改完。
