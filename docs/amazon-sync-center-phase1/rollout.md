# 启用、部署与回滚方案（未执行生产操作）

## 试点启用顺序

1. 确认全部工作区改动的 GitHub 提交范围；当前混有非本任务修改，不能静默选文件发布。
2. 审核 SQL，确认生产备份、容量和索引／锁表窗口。通过既有 CI artifact 发布链路执行必要 generate / migrate deploy；本地已验证的是一次性隔离库，不是生产库。
3. 先部署兼容版本，保持 `AMAZON_SYNC_CENTER_SCOPES` 缺省或 `[]`。新表默认不启用，旧任务／计划继续 v1。
4. 在旧设置中暂停目标范围库存与在线商品旧计划，等待 QUEUED/RUNNING 旧任务排空；中心会拒绝在旧任务未排空时绑定／创建任务。保留旧凭证及配置。
5. web 和 amazon-sync-worker 配置一致的精确 JSON，例如 `AMAZON_SYNC_CENTER_SCOPES='[["实际组织ID","实际工作区ID"]]'`。无通配符，非法配置默认关闭。保留既有 QUEUE_DRIVER=redis、DATABASE_URL、REDIS_URL 和加密密钥配置，不将真实值写入文档。
6. 管理员在“店铺与授权”新增或显式导入旧数据库凭证；明确填写卖家身份和区域，验证参与站点，再绑定 ERP 店铺＋站点＋域。导入不自动启用计划、不推断卖家。
7. 先手动执行单站点库存／刊登，确认完整分页、成功清单、源归属、零行语义、商品只读关联及补货兼容；再建立停用计划、审核后启用。默认建议库存 60 分钟、刊登 24 小时，可修改。
8. 观察实际 Amazon 授权／限流、内存、数据库增长和 Worker 心跳后再增加店铺。不要直接把模拟容量结果当生产预算。

本轮没有修改 .env 或部署清单；上线必须由用户另行明确要求，沿仓库 CI artifact 链路执行。涉及 schema、Worker、共享 lib，按部署清单仅迁移与重启所需进程；不默认重启其他服务或修改 infra。

## 回滚

- 先暂停新计划、取消或等待活动任务退出，再关闭目标开关。页面和查询恢复兼容旧路径，保留 v2 数据与扩展表；关闭开关不是数据库回滚。
- 保留本轮兼容应用版本运行。**不能直接回滚到任意迁移前应用**：旧 Prisma upsert 唯一键不包含 planKey，无法兼容扩展后的多计划模式。需要回滚应用时选择已适配新 schema 的兼容版本。
- 确认新调度停止后，按需恢复旧计划并重新完整同步，避免 v1/v2 同时运行。关闭开关时旧快照可能较旧，需向运营展示实际新鲜度。
- 数据库只向前迁移，不执行删表或 migrate down；快照与日志按保留策略清理，当前与补货引用保护。
- 加密密钥需保持稳定，丢失后无法恢复检查点或凭证。若发生泄漏应按受控流程轮换凭证，不能把密钥写进诊断日志。

## 待完成的发布门槛

完整 CI、真实店铺最小联调、实际发布产物与权限验证、生产任务杀进程恢复、P95／内存／容量预算及多用户负载。全仓 check:fast 已通过；CI 构建及其他发布门槛完成后才能发布。报告／订单／财务不得因 Phase 1 发布被自动启用。

## 本地真实联调（独立于生产发布）

按 [live-validation.md](live-validation.md) 执行单 Seller／Marketplace 只读验收；先运行 `node scripts/amazon-sync-live-preflight.mjs`，它不连接服务、不解密凭证、不请求 Amazon。预检不能证明真实验收。当前预检单一精确试点范围未通过；真实身份及专用本地库／Redis 须人工确认。不要直接把本节生产步骤用于本地准备。

## 当前本地新库模式（覆盖前文旧页面回退步骤）

按最新要求，/operations 仅展示新同步中心及合并后的业务页面，不提供旧页回退、旧链接映射或旧凭证导入。当前使用独立新库，不执行旧数据迁移；试点开关关闭只显示未启用错误，不切换旧工作台。上述旧版兼容发布／回退步骤是历史记录，不应作为当前本地运行操作。当前未授权发布，仍不得推送／生产迁移／部署。
