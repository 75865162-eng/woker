隔离浏览器参数化覆盖验证和停用的延迟申请、就地错误、重试与审批入口；增加停用完整模拟路径，检查提交和批准都不改授权状态，显式应用后才显示已停用并禁用按钮。没有提交、批准、应用真实停用，也没有请求真实服务。回滚仅撤销本节 UI 与测试增量；无需修改数据库或恢复真实授权。真实操作由用户自行验证。

## 授权验证错误来源与详细解释

用户要求错误更详细，并在 Amazon 返回内容前加“亚马逊返回：”。本次在现有字符串错误字段与授权卡片内实现，不新增 API 字段、数据库字段或迁移：

- 新验证即时失败：只有现有 `AmazonSpApiError` 带 HTTP status 的响应才加“亚马逊返回：”，展示 SP-API client 已限长、脱敏的 HTTP 状态和返回说明；客户端已移除所用凭证/访问 Token。网络/超时使用“连接异常：”及网络/代理检查建议，不伪称上游回复。未知异常保持固定系统错误，不返回内部异常内容。
- 历史授权卡片：`AUTH_REJECTED` 表明响应被归类为授权拒绝，注明“根据响应分类；该历史记录未保存返回原文”，另列核对 LWA 三项凭证、同一应用、卖家撤权与 API 权限的排查建议，并明确这些是方向而非已确认原因。`INVALID_PARTICIPATIONS` 与未知分类分别说明本地结果校验、网络/服务等可能性，保留分类码及最近尝试时间。
- 历史记录以及新验证刷新后的卡片仍只读取既有分类码，不能还原 HTTP 状态和原文；本次没有将原始响应落库或从历史记录猜造详情。若未来要持久查看具体脱敏响应，需另行评审存储/API 扩展、保留期与安全边界。

模拟服务回归覆盖 LWA 400、SP-API 403、网络失败及空参与站点：只有真实模拟 HTTP 错误标识上游返回，三项凭证及 access token 不出现在错误消息中。模拟浏览器检查历史卡片的来源说明、排查建议和分类码。没有读取/修改真实凭证、重试真实验证或调用 Amazon；未提交、推送、部署。回滚仅撤销本节错误文字和测试增量，不影响审批或历史数据。
