# 报关资料、货件资料与核算草稿核心流程

在现有头程计划统一 service/API/页面内补充：货件→箱→SKU 三层费用分摊，每层最大余数法对平，逐层保存依据；按已关联货件数量及当前装箱校验，拒绝外部货件、漏箱和超量。装箱新增可选净重，缺失保持未知。报关主档/明细留存品名、HS 编码、原产国、单位、数量、精确申报金额，另一名有 WMS 审批权限且具备店铺读取权限的人员内部复核后，创建人可登记申报/查验/放行/退回回执；这是人工证据，不执行申报。参考 Wimoor `inboundV2/pojo/entity/ShipInboundCustomsXml.java` 和 `ShipInboundCustomsXmlItem.java` 的资料与计价职责，源码涉及 CEB 单据，不能视为 Amazon CBP 标准；导出的 `urn:erp:customs-draft:1` 是内部 XML，正式国家模板/XSD 尚未配置。

预约回执、保险保单和柜单使用分类型严格合同，保存于同一资料表；保单可关联本计划保险费，柜单拒绝重复占箱或超过关联货件数量，存在有效柜单时禁止改写装箱。注销只注销本地登记并保留原记录和依据，不取消外部预约/投保。财务差异可录入拟用账套、期间和逐明细成本科目，保存借贷平衡凭证草稿及原规则输入；支持零净差额的 SKU 重分摊，及明确方向/来源/时点的十二位汇率快照换算。总额六位 HALF_UP 后分配明细尾差。规则草稿可双人复核，仍标记未核验正式总账配置、未过账；纯总账试算/冲销/结账规则沿用现有 `src/lib/finance/rules.ts`。

本批新增五表、七个租户复合外键，三个迁移 `20261125010000_fba_local_customs`、`20261126010000_fba_local_finance_draft`、`20261127010000_fba_local_shipment_documents` 已依会话授权限定应用于根 `.env` 的本地 `amazon_sync_live_local`，核验 Docker/数据库身份、前置迁移、完成记录/校验和与新表约束，原业务记录数量不变。回退停用新增动作并保留表/证据，不自动删表或反向迁移。验证使用无根环境/真实凭据的临时 PostgreSQL、会话 HTTP、并发重试、撤权/隔离/回滚和 Chromium 保存刷新及原 WMS 出库全流程；规则测试、类型检查、定向 lint、diff 检查随代码验证。另修复仓库页面一处 JSX 缺失闭括号以解除出库回归阻断。合并前仍需完整 `npm run check`；未提交、推送或部署。
