## 操作流程

1. 在头程费用差异卡片完成规则独立复核，或在库存财务草稿中完成计价，复制核算草稿 ID。
2. 打开现有“ERP 总账”，选取正式账套与开放期间；在“核算来源转入”选择来源类型并预览。
3. 对每个来源科目选择正式末级科目，确认币种、分录与会计日期，保存总账草稿。
4. 另一名具备总账审核权限的人员审核，再按已有流程过账。费用来源复核与正式总账审核各自独立。
5. 发现已过账金额错误时按原凭证生成红字草稿并审核/过账；来源尚未创建成功时重试恢复，不虚构冲销。

来源交接边界：单来源单币种、2–200 条有效分录；不同来源科目暂不允许合并映射。换汇在来源端明确完成，不隐式使用最新汇率。跨期间的记账日期由财务指定并经服务端期间校验。

- **0–3 个月**：本轮首批交接验收；补 FBA 外部合同、采购/仓库实际流程与 AP 余额。以一个组织/工作区和明确试点商品/仓库范围核对；不因此取消平台隔离。培训先覆盖草稿、审批、实物与观察状态差别及异常重试。
- **3–6 个月**：落实估值制度、采购/货代核销、费用归集及来源去重；建立子账到总账对账和完整业务关账。由财务签署期初、未结单和差异处理规则，再另行审批业务数据迁入。
- **6–12 个月**：扩展需求预测、预算、经营看板和 AI 草稿建议，优化扫码/批处理；按实际吞吐与 P95 决定优化，不按人数推导技术改造。

月份为路线建议，不是开发完成承诺。每批须有功能负责人、独立审核人和异常处理人；通过同一来源追踪到单据、数量、金额及审计。上线切换先培训演练，再限定来源核对，避免试点账与原账重复入账。

## 运维、迁移与回退

当前新增 Prisma 模型与迁移/证据保护触发器，复用现有注册 import Worker 扫描显式启用的库龄计划；未新增队列注册、修改环境或公共导航。迁移 `20261210010000_three_core_completion`、`20261210020000_wms_aging_schedule`、`20261210030000_fba_workflow_options` 包含相应索引、跨账套/仓库外键和不可变证据约束。真实环境接入前另行核验、批准相关迁移；禁止自动迁移已有库。

按既有 Worker manager 与 CI artifact + deployment-plan 管理任务与发布。监控关注来源导入失败/冲突、待补成本数量、事件滞后和失败重试、未过账来源、期间锁冲突。日志保留关联 ID 和固定错误分类，不输出原件、凭据或完整来源 payload。

备份沿现有运行文档列目标、恢复演练和审批；本轮不启动备份。日常分别对公司仓数量、在途、Amazon 实收、采购/货代应付、支付核销及总账借贷核对。物流签收不代表 Amazon 实收。

回退停止新增来源导入动作并保留已提交草稿、来源键及审计。已审核/过账事实走正式冲销和更正，不删凭证、不反向迁移、不假设代码回退能撤销实物发货。

本轮实际验证与限制以 [validation](../../specs/010-fba-wms-ledger/validation.md) 为准；未提交、推送或部署。

## 继续全量结构核对后的补齐

本节替代前文相应“待接通”条目；依然只在当前本地工作树及临时资源验证。

- FBA：源 SDK 现提取 **134 个可达请求/响应 DTO**（仍为45操作、50请求DTO）。成功 GET 与外部动作同事务保存 `FbaRemoteReadSnapshot`，按源响应字段投影计划、货件、箱、箱商品、托盘和方案，原始加密回包与精确小数字符串可追溯。分页状态只表示单响应页面，不宣称全计划完整；不覆盖本地装箱、不产生实收。明确 GET 的失败/发送租约过期结束为 FAILED，可以新建独立审批请求；原动作不自动重发，写操作未知结果保持阻断。
- WMS：库存历史统一查询新增完整 UTC 日/月收发存分类与数量守恒，最多100库存位置分页、每日最多31天；收货不自动等于采购，周转率/周转天数无政策保持null。盘点详情提供仓/库位/批次毛额盘盈盘亏，盲盘隐藏基准和差异。海外最终费用按数量/计费重/体积/货值逐箱逐行分摊，留存同币种预估差额、独立审核、不可变证据；通过 `WMS_OVERSEAS_CHARGE` 显式科目映射为总账草稿，不直接改库存成本。
- 财务：科目类别1–3级、系统固定标记、revision编辑/停用/未引用删除；项目复用辅助目录并保留历史维度，银行账户具支付方式/默认唯一/停用状态；按项目、账户和月份派生已过账收支及正式期初余额。库存来源交接保存商品/批次/仓/数量/单价与正式分录行号的不可变辅助证据。新增独立审核的字段凭证模板，明确摘要/科目/借贷方向/精确受限表达式，来源值预览摘要后只创建草稿。
- Ads：财务来源拒绝不同 API 合同的观察事实混合入账；API版本与币种/归因窗口均保留。v3报表与Ads API Reporting v1是独立合同，不整体改为虚构v3.1。SP/Ads对齐证据索引已从历史 INITIAL_MATRIX 定向更新到当前实现；真实最新官方、账户权限和额度验收不由源SDK证明。

新增迁移 `20261211040000_three_core_remaining_structure`。现存科目类别通过递归回填层级；超过3层或不可达树明确阻断迁移，不能静默截断。迁移须在真正上线前独立审查与批准，本轮不对既有数据库执行。

当前99行候选中34项由目标现有能力承担、65项部分覆盖；全部 `fullSourceParityVerified=false`。详见[当前覆盖](three-core-current-coverage.md)、[财务源字段证据](finance-remaining-structure.md)与[最新验证](../../specs/010-fba-wms-ledger/validation.md)。剩余部分覆盖主要含源全部历史样式/公式、第三方真实执行、目标政策口径与线上验收，不应为消除 PARTIAL 而重复建表或冒造业务事实。
