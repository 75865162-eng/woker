## 2. 必须修正的原文判断

| 原文判断 | 评审结论与替代要求 |
| --- | --- |
| 全部对齐 SP-API `2024-09-01` | 错误。SP-API 按 API 家族分别版本化；Inbound 依指定指南和当前实现采用 `2024-03-20`。每个 Operation 记录版本、路径、角色、站点、请求/响应和异步机制。 |
| 所有旧 `v0` 都删除 | 不能按版本名删除。指南仍列有合法 v0 API；Inbound v0 也应按具体操作的移除及替代情况处理。保留历史归档和必要读取能力，删除执行分支前核对实际调用方。 |
| 配额使用 `fba.inventory.restrictions/getInventoryRestrictions` | 当前指定资料和已读实现未提供该合同证据。不得据此实现或填充“SKU 可发数量”。Listing 限制、入库资格、库容/容量和某次计划校验是不同概念。未确认配额保留未知状态，不以库存量或零替代。 |
| Amazon 强制 CBP XML，旧 PDF 字段全部作废 | 证据不足。出口报关、美国进口申报、货代单据与 Amazon 装箱/标签分别建契约；适用国家、申报责任人和 Schema 待核实。保留有效历史附件与字段，不按文件格式判废。 |
| Ads 统一升级到 `v3.1`，老 SearchTerm 报表删除 | 无统一版本依据。当前 SP 实体读取使用各自 v3 media type；Reporting、Export、SP/SB/SD 分开核实。搜索词是业务粒度，不能由某旧接口退役推断整个粒度废弃。 |
| 30 人内部使用，删除所有租户隔离字段 | 不采纳。人数不改变当前 Organization/Workspace 及权限边界；沿用现有隔离。无依赖的 SaaS 计费逻辑可单独评审，不与隔离机制一起删除。 |
| 建 `amz_shop/amz_sku`，`shopId+fnsku` 是唯一标识 | 不另造商品主档。沿用 ProductRecord 与现有账号/站点映射；sellerSku、ASIN、FNSKU 可空且语义不同，不能用 FNSKU 作为所有业务身份。 |
| 跨模块禁止 import Service，全部 BullMQ 事件 | 过度规定。保留既有明确服务合同；可靠异步交接采用数据库 Outbox/消费幂等，BullMQ 负责投递，Redis 不是事实源。不能为事件化拆坏现有采购收货事务。 |
| `spApiRequestId` 防重复创建货件 | 错误。请求 ID 用于追踪；本地业务幂等键、请求摘要、唯一约束、外部 operation/实体关联及未知结果核实共同防重。不得假设 Amazon 支持任意自定义幂等 Header。 |
| 创建计划冻结，确认货件扣减，签收就 WMS 入库 | 将外部状态与实物作业混同。内部计划是否成功预占须单独确认；实物出库依 WMS 审批执行；Amazon 声明数量/物流签收不直接代表实际接收数量，更不能增加公司仓余额。 |
| WMS 加 `WmsStockFreeze`，四级盘点原样保留 | 当前有 WmsReservation，未见该冻结模型。预占和质检/盘点冻结语义先分清；“全盘、抽盘、动销、盲盘”包含可组合维度，不是已证实的四层流程。 |
| 财务失败就红字冲销 | 尚未成功过账时记录失败并幂等恢复，不生成无原凭证的冲销。错误的已过账凭证才通过关联冲销和更正处理；会计失败不自动逆转实物出库。 |
| 日拉 Ads/订单收入，自动生成收入凭证 | 采集不等于入账。广告通常属于费用；订单不等于结算/收入确认事实。先标准化来源、去重、对账，再按财务确认规则生成待审凭证；禁止重复计算广告费、平台费或退款。 |
| 结账绝对不可逆；批次与加权平均原样沿用 | 采用期间锁定；是否允许受控反结账由财务制度决定，不开放任意改历史账。批次追踪与成本计价层级分别定义；不能从“加权平均”推断在每批次重算。 |

## 4. 统一身份、事务与事件合同

### 4.1 身份及字段映射

以下为目标语义，不是批准新增全部字段；落模前先复用现有类型和索引。

| 概念/原文字段 | 目标约束 |
| --- | --- |
| merchantId | 不直接替代 organizationId。若代表法律核算主体，需单独确认其与组织、账簿和工作区的关系 |
| shopId / marketplaceId | 沿用现有 ERP account 与 site 映射；区分内部账号 ID、真实 Seller ID 和 Amazon marketplace ID，每次读取/执行实时授权 |
| skuId | 当前商品引用使用 productRecordId；库存作业细到 WmsLot/location，Amazon 商品身份通过经核实的映射关联 |
| planNo / spApiInboundPlanId | 内部业务单号与 Amazon inboundPlanId 分离；唯一范围至少涵盖组织、工作区及外部账号身份，跨站点关系按官方合同确定 |
| placementOptionId | 属于相应外部计划和方案版本，保存可选项、费用/币种、有效性及确认结果；不作为计划唯一长期属性覆盖历史 |
| spApiShipmentId / warehouseId | 区分外部 shipmentId、shipmentConfirmationId、Amazon 目的仓标识与内部 WmsWarehouse.id |
| planQty / declaredQuantity | 计划、装箱、公司仓实发、Amazon 实收、差异分别记录；缺失实收保留 null |
| packingInformation | 每箱尺寸/重量带单位，箱内商品/批次/有效期按合同；包装分组、箱型、贴标/预处理责任枚举逐字段核实 |
| 标签 base64 | 普通业务 DTO 返回受控文件引用及摘要；不默认数据库内嵌大体积 base64，不混同商品标签、箱标与承运面单 |
| amzRestrictionQty | 无已确认来源时不作为可发额度事实；记录限制类型、来源、观测时间、范围和有效性后才参与校验 |
| 金额/汇率/体积/重量 | 明确字符串/Decimal、币种/单位、精度与舍入；数量继续沿正式计数合同，不一律字符串化 |

### 4.2 本地事务与可靠异步交接

业务聚合内：实时授权、revision/状态、幂等键及 requestHash、单据、流水、审计和必要 Outbox 在同一数据库事务提交。已有采购→WMS 合同先保留，避免大范围改事务与失败语义。

新增异步交接时采用数据库 Outbox → 已注册 Worker → 消费端事务。目标事件信封至少包括 eventId、eventType、schemaVersion、organizationId、workspaceId、aggregateType/id/revision、occurredAt、correlationId/causationId 和受限 payload；外部账号/站点按业务需要显式携带。消费者按消费方与 eventId 唯一登记，副作用和去重记录同事务提交。允许重复投递，不承诺恰好一次；旧 revision、乱序或缺少先决事件进入等待/核对，不覆盖较新事实。

Outbox 投递状态、租约、退避、失败待办、重放与业务幂等结果持久化；数据库提交后队列失败可恢复。先确认现有 Outbox 是否能扩展，不把 Product 专用 Outbox 无条件改为通用总线。本次只提出需求，不新增队列/消费者。

### 4.3 事件及命令的建议分工

| 交接 | 条件与结果 |
| --- | --- |
| FBA 本地计划申请预占 | 作为带 revision/范围的 WMS 命令；库存成功后返回预占单引用。失败时计划保持待库存，不能对外显示已预占 |
| WMS 预占/释放完成 | 事实事件关联具体命令、计划和数量，FBA 更新交接进度；重复事件不重复预占 |
| WMS 实物出库完成 | 关联拣货/批准/出库流水；形成公司仓减少和在途业务证据。外部货件确认本身不触发第二次扣减 |
| Amazon 货件/接收观察更新 | 来源归档和观察版本明确；物流 DELIVERED 与 Amazon 逐 SKU 实收分开，差异进入核对，不改公司仓现存量 |
| 成本来源确认/更正 | 财务对源单 revision 幂等处理；数量事件不能默认为已具备金额和会计科目 |
| 凭证过账/冲销完成 | 发布已提交事实供报表读取；财务失败进入待处理，不用 BillCreated 这个含糊事件代替状态合同 |

## 5. 模块 A：FBA 头程接入

### 5.1 分阶段工作流

1. **本地计划**：选择同范围商品与来源仓/批次，校验账号/站点映射，形成草稿、审批和预占结果；尚未创建 Amazon 计划时不造外部 ID。
2. **外部计划与装箱**：取得并验证写 Operation Schema 后，对接创建、异步结果核实、packing options/groups 和装箱提交。原文 `packingInformation` 不能代替准确的 Operation 名、路径及请求合同。
3. **分仓、运输、配送窗口**：按 Amazon 返回的可选方案及适用流程展示费用/期限，经批准确认；本地允许做方案比较与配载，不伪造 Amazon 分仓结果。先后次序、可跳步骤和修改失效关系依站点/工作流官方合同确定，不锁死单一路径。
4. **标签与实发**：受控取得标签，WMS 按实物完成拣货、出库；外部确认/跟踪更新与仓库出库分别记录，保存彼此关联。
5. **接收与差异**：结合有明确数量语义的来源记录分批实收、短溢收、关闭和索赔证据。到港、承运商签收、Amazon receiving/closed 是不同事实。

本地状态建议：DRAFT、AWAITING_APPROVAL、AWAITING_STOCK、READY、SUBMITTING、EXTERNAL_PENDING、SUCCEEDED、FAILED、RESULT_UNKNOWN、CANCEL_REQUESTED、CANCELLED。此为待设计状态集，不能直接当所有单据通用枚举；计划、步骤和命令分别定义合法转移，Amazon sourceStatus 原样留存并单独映射。

### 5.2 幂等、恢复及契约进入条件

- 写命令持久化 scope、Operation/API 版本、请求摘要、内部 revision、审批引用、尝试记录和外部标识。Request ID 只是诊断关联；operationId 用于官方异步流程，和业务幂等键不同。
- 超时或进程中断可能发生在 Amazon 已成功、本地尚未记录之间；标记 RESULT_UNKNOWN，优先按已有 operationId/实体 ID 核实。缺少可靠找回方法时进入人工核对，禁止盲重试创建。
- 并发编辑或重新装箱后，相关报价、分仓/运输选项及审批按合同失效。审批成功仍需执行时实时复核授权、范围、revision 和有效期。
- 逐 Operation 补充角色、地区可用性、分页、实际限流、Retry-After、异步轮询、错误分类和敏感归档。不能在方案中编造统一 TPS。
- 首期交付本地状态与模拟外部边界测试；真实 Amazon 写动作单独审批。已有正式执行端及 Worker 管理保持现状。

### 5.3 报关和费用

报关按国家/贸易方式/申报主体/货代渠道独立建资料版本：品名、HS、原产地、数量/单位、币种/价值及证据附件。XML/XSD 或 PDF 模板必须来自明确主管机关/服务方和适用版本，先验证再导出，不能自称 Amazon 强制 Schema。

头程费用保留估算与实结两个阶段；按重量、体积、数量或货值分摊必须定义分母、排除项、缺失数据和余差。不强制所有费用都经“货件→箱→SKU”三次分摊：费用来源直接归属的按直接归属，不可因多层舍入制造误差。分摊方案带版本，结果合计与原费用一致；差额生成待审核成本调整，不自动改历史凭证。

## 6. 模块 B：WMS 增量接入

- 复用 WmsReservation 表达 FBA 可用库存预占。盘点/质检冻结是否另建模型、是否可与预占重叠，先列状态与余额不变量；同一数量不得重复扣可用库存。
- 在现有收货与流水来源合同上补采购、退货、调拨、FBA 退回等正式身份。Amazon 客退报告不证明公司仓已收货，只有实际接收、验货和批准操作产生公司仓流水。
- 数量账和成本账职责分离：WMS 保存数量、来源和批次/库位，成本账保存估价与调整。允许入库数量已确认而成本待核；财务延迟不能把未知采购价补成零或阻塞已批准的实物事实留存。
- 库存流水不可因财务重算原地改写。成本使用可追溯追加记录关联 movement/source line，晚到运费、退货、短收与关闭期间按财务制度调整。
- 盘点定义范围（全量/抽样/动销）、是否盲盘、冻结/截止时点、复盘、差异审批和调整命令；这些是组合条件，不先建“四级盘点”硬编码。
- 库龄必须明确公司仓首次收货、批次转移、退货和 FBA 实收各自口径。日快照的时区、完整性和补算幂等先定；库龄不直接等于财务减值，应由财务政策决定。
- 第三方 WMS 字段仅在确认无调用/业务依赖后排除；不能因“自建仓”删除所有外部单据关联和历史证据。

## 7. 模块 C：成本、应收应付及总账

### 7.1 建设顺序与模型职责

先确认法律核算主体、本位币、期间/时区、税费处理及科目制度；采用现有组织和权限，账簿身份不能由客户端 merchantId 推断。

建议顺序为来源交易标准化 → 采购/货代应付及付款核销 → SKU/库存成本与分摊 → 科目/期间/凭证 → 过账/账簿 → 对账/结账。不以“46 表”为验收目标。以下是拟建职责，正式 Prisma 名称和字段待切片设计：

| 对象 | 关键不变量 |
| --- | --- |
| 来源交易/会计事件 | 保留来源系统、对象/明细、业务 revision、金额币种及实际/估算属性；跨重叠报告识别同一交易，版本更新不重复计费 |
| 成本台账/分摊版本 | 数量来源、估值单位、计价层级、汇率及余差可追溯；与实物流及凭证分别关联 |
| 应收应付/核销 | 原始债权债务、付款、退款、部分核销和余额分开；付款不自动等于费用确认 |
| 科目/期间/凭证 | 原币与本位币分开；凭证头/明细、来源和审批完整；同一来源过账规则幂等 |
| 汇率证据 | 记交易/记账日期、来源、币种对及精度；不是所有业务统一用“每日最新汇率” |
| 账簿/余额/结账记录 | 可由已过账凭证明细核对，期间并发锁定；审计与重建机制明确，不引入第二套可随意写的金额事实 |

### 7.2 成本及 Amazon 费用口径

移动加权平均的基础形式为 `(原库存成本额 + 本次可资本化入库成本额) / (原数量 + 本次合格入库数量)`，只在选定估值范围、数量及币种可比较且分母有效时使用。批次追踪不强制按批次独立计价；费用/税额能否资本化由会计政策决定。零库存、负数调整、采购退回、晚到费用、已售数量及跨期差额必须有独立规则和验证样例。

Ads 报告可用于经营分析或费用暂估；发票/账单/支付及平台扣费需对账，报告修订作为更正而非新费用。广告费用未必能准确归属所有 SKU，保留账号/活动级未分摊金额及方法，不能强行按广告销售额制造 SKU 精确利润。

订单、退款、财务交易、结算、仓储费报告可能重叠；逐来源定义唯一事实和关联，不把同一费用重复入账。订单金额不能直接当已结算现金；FBA 配送/佣金/退款/赔偿分别映射规则。总账核心与外部 API 解耦，来源适配器仍依赖 SP-API/Ads 及数据质量，不能称整个财务链完全不依赖 API。

### 7.3 审核、过账、冲销和结账

- 草稿、审核、过账、冲销分别定义；已审核或已过账凭证禁止原地改写，按财务制度以可追溯更正/冲销处理。生成失败没有原过账记录时只重试，不做虚假红冲。
- 过账在事务内校验借贷本位币总额相等、科目有效、来源幂等及期间开放；借贷平衡是必要条件，仍需金额、来源和科目正确。
- 结账检查未处理交易、成本异常、来源缺口、应收应付/银行/结算对账及子账总账一致。不能仅凭试算平衡结账。
- 结账和过账并发使用同一期间保护协议。关闭期间拒绝普通写入；默认以开放期调整，确需反结账则指定权限、双人审批、后续期间处理及完整审计，由财务负责人确认制度后实现。
