已实现并验证：

- 多商品出库需求 → 按库位/批次分配预占 → 拣货/撤拣 → 审批发货；草稿编辑、取消与需求数量上限沿现有服务执行。
- 在途调拨单与明细：部分发出、部分签收、在途量、完成及未发出草稿取消；发出扣来源，签收才增目的，同批次保留；在途目的范围禁止停用。
- SKU 等量同仓转换：显式目标商品批次，原主档/批次不变；独立审批、成对流水及完整反向冲销；每个原转换最多冲销一次。
- 出库耗材：主商品需求、耗材商品、六位小数耗用比例；实际出库后独立审批发料，限制已出库未计量数量，比例须精确组成整数库存单位，不截断小数。当前草稿规则建立后不提供删除/改比率操作，修订通过取消草稿重建。
- 自定义仓库类型、可编辑地址、库位长宽高（厘米）及容量（立方米）；高精度值跨 API 使用字符串。容量是资料字段，未启用自动占容。
- 任意已发生 UTC 期间（≤366 天）的历史库存/日月期间查询：期初、入出、期末和数量桶由流水派生；余额与全流水不一致时返回 NEEDS_DATA/null。
- Wimoor 快照减后续出库的周转区间估算：30/60/90/180/365 天。按仓库和正式商品身份聚合；同一命令在同仓同商品的双腿净额抵消，保留缺数据状态。这是周转估算，非 FIFO 批次库龄或 Amazon 零售销量。
