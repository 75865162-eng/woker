# 独立费用与货代对账

现有头程工作台及 `/api/operations/fba-local-plans` 接入 `CREATE_FEE_RECORD`、`CONFIRM_FORWARDER_BILL`，复用统一计划 service 的实时 WMS edit、计划创建人和店铺/站点授权。每计划最多 100 笔独立费用，支持海运、空运、燃油、报关、清关、保险、拖车及其他；旧单笔计划草稿仍保留原用途，不自动转成费用台账，也不计入台账合计。

`FbaLocalFee` 保存不可覆盖的预估分摊；`FbaLocalForwarderBill` 保存实际账单、货代和逐计划明细对账；`FbaLocalCostAdjustment` 保存待核算映射的差额交接草稿。显式零实际金额允许，缺失金额拒绝；总额不变但明细分摊变化也保留调整请求。币种不同拒绝自动换汇。账单、调整、计划 revision 和审计在同一事务提交；计划取消保留这些证据。

调整记录状态为 `NEEDS_ACCOUNT_MAPPING`，不是已生成的正式凭证。当前未持久化正式账套、科目及期间，不能据此过账、付款或计入库存估值。沿用上批已移植的精确分摊和财务差异规则，不复制 Wimoor“保存即记账”行为。

新增迁移 `20261122010000_fba_local_fee_ledger` 先通过一次性 PostgreSQL 验证，再沿用本会话明确的迁移授权，应用到根 `.env` 指定的本地 `amazon_sync_live_local`。执行前比对 Docker 容器镜像、端口映射、数据库名称及实际服务端 IP，只应用本次一个增量；执行后核验三张表、三个复合租户外键、迁移完成记录、文件校验和及原计划数量不变。未执行其他待迁移项。停止新操作入口可回退使用，保留表、账单、调整及审计，不自动删除数据。

验证：临时库完整迁移链、真实数据库会话 HTTP 隔离/撤权/版本/并发幂等/故障回滚，以及临时 Next + Chromium 录预估→确认实际账单→差额草稿→刷新回读，并回归双人预占与出库。全部使用合成 fixture，未访问真实 Amazon、未验证真实货代账单。本批新增三个业务对象，不能宣称完整 38 个对象或正式总账链路完成。
