# woker vs wimoor — UI / 交互层实测差距与本地升级清单

> 实测环境：两个系统均在本地完整拉起并登录，浏览器截图逐页对比。
> - woker：`http://127.0.0.1:3000`（Next.js 15 + PostgreSQL/Redis，本地 seed admin）
> - wimoor：`http://127.0.0.1:8084`（Vue3 + Vite 前端 → Nacos + 5 个 Spring Boot 微服务 + MySQL8/Redis）
> - 对比日期：2026-11-23。截图见 `/workspace/ui-compare/`。
>
> 本清单只讨论 **UI / 交互**，功能层差距见 `wimoor-vs-woker-gap-and-migration-plan.md`。

## 0. 结论先行

在 UI/交互层，**woker 整体明显领先 wimoor 一代**：woker 是现代 SaaS 工作台范式（分组导航 + 全局上下文 + 标签页 + 统计卡 + 多列排序 + 可钉住列），wimoor 是传统 ERP 后台范式（深色窄栏 + 彩色胶囊按钮 + 渐变横幅）。

但通过逐页实测，仍发现 **woker 自身有 6 个可落地的交互短板**，其中 3 个是“wimoor 有而我方缺”的真实差距（值得补），3 个是我方体验瑕疵（值得修）。下面按优先级给出。

---

## 1. 导航层

| 维度 | wimoor（实测） | woker（实测） | 判定 |
| --- | --- | --- | --- |
| 侧栏形态 | 深色窄栏，仅图标+单字，首屏只露“系统” | 浅色宽栏，图标+文字+二级展开箭头 | woker 优 |
| 分组展开 | 无（模块靠后端动态菜单） | 7 大分组可展开，子项可“钉住/拖拽排序” | woker 优 |
| 全局上下文 | 无 | 顶部“全局工作区/店铺上下文”切换，宣称全站生效 | woker 优（独有） |
| 标签页多开 | 无（单页跳转） | 多标签页（工作台/商品主档…可关闭） | woker 优（独有） |
| **子页快速固定** | 无 | “固定到侧栏 商品主档/计算器中心” | woker 优（独有） |

**差距 W1（真实缺口，P1）**：wimoor 侧栏虽简，但**模块名即入口**（产品/销售/采购/仓库/发货/广告/账目/财务 12 个顶级模块一眼可见）；woker 侧栏分组是业务域（商品管理/赛狐数据…），**缺少“按业务动作直达”的一级入口**。用户找“采购单/发货单”这类高频对象要多点一层。
> 建议：在侧栏顶部或工作台增加“高频功能直达区”（采购单 / 发货单 / 产品列表 / 利润报表 4 个锚点），降低点击深度。

## 2. 列表页 / 表格交互

| 维度 | wimoor（实测） | woker（实测） | 判定 |
| --- | --- | --- | --- |
| 筛选区 | 卡片入口为主，列表页有筛选 | 完整筛选区（搜索/下拉/价格区间/查询/重置） | 相当 |
| 列排序 | 传统表头点击 | 每列独立“按 X 排序”按钮，6 列可排 | woker 优 |
| 统计维度 tab | 无 | 6 个状态 tab（全部/开发中/运营确认中/美工处理中/运营进度/超期预警/我的SKU） | woker 优（独有） |
| 批量操作 | 有（ERP 强项） | **未观察到批量勾选/批量编辑条** | **wimoor 优（真实差距 W2）** |
| 列配置/密度 | 有 | 未观察到 | wimoor 略优 |
| 分页 | 有 | 上一页/下一页（当前无数据 disabled） | 相当 |

**差距 W2（真实缺口，P2）**：wimoor 作为写系统，列表页有成熟的**批量勾选 + 批量操作条**（批量审核/批量改价/批量导出）；woker 当前商品列表以只读+单条操作为主，缺少批量选择交互。由于 woker 架构红线是“只读工作台”，不宜照搬写操作，但**“批量选中 → 批量导出所选 / 批量复制 SKU / 批量加入对比”这类只读批量动作**是安全且高价值的。
> 建议：给商品主档列表加“行勾选 + 批量导出所选 + 批量复制 SKU”只读批量条。

## 4. woker 自身 3 个体验瑕疵（本次实测发现，建议本地修）

| 编号 | 问题 | 证据 | 建议 |
| --- | --- | --- | --- |
| S1 | 首页指标多为 0 / `—`（销量、订单、FBA库存全 0） | 本地 seed 后无业务数据，指标卡全是 0，趋势图空 | 复核后判定为**数据问题非 UI bug**，且 0 是 `value=0` 真实值；不改 KPI 卡以免误导（遵守“不造数”红线）。已在首页入口区提供数据源直达，不再单独改卡 |
| S2 | 标签页“关闭”按钮视觉弱 ✅ 已修 | 原为 `h-4 w-4`(16px) × | 改为 `h-5 w-5`(20px) + hover 加深 + `active:scale-95`（本次已落地） |
| S3 | 侧栏子项“钉住”图标语义 — 复核后**无需改** | 复核代码：`PinnedRow` 与业务菜单浮层均已有 `aria-label`/`title`（“固定到侧栏 X”/“取消固定 X”） | 原判断偏保守，代码本已达标，不重复改动 |

## 5. 本地交互升级落地清单（按 ROI 排序）

| 优先级 | 项 | 类型 | 状态 | 架构风险 |
| --- | --- | --- | --- | --- |
| **P0** | S2 标签关闭热区 16→20px + hover 加深 + 点击缩放 | 体验瑕疵修复 | ✅ **已落地**（`workspace-tabs.tsx`） | 无 |
| **P1** | W1 工作台“高频业务直达区”（产品列表/销量统计/利润报表/采购订单，带权限过滤） | 真实差距补齐 | ✅ **已落地**（`(erp)/page.tsx`） | 无（纯前端，复用 `roleCanAccessModule`） |
| — | S3 子项钉住 tooltip | 复核无需改 | ⏭ 代码已有 `aria-label`/`title`，跳过 | 无 |
| — | S1 空指标卡 CTA | 复核判定不宜改 | ⏭ 0 为真实值，改卡会误导；跳过 | 无 |
| **P2** | W2 商品列表“只读批量条”（勾选/导出/复制 SKU） | 真实差距补齐 | ⬜ 待评估（需读商品列表组件，确认只读动作边界） | 低（只读动作，不写核心主档） |

验证：`npm run typecheck` 与 `npx eslint`（改动文件）均通过。

> 不纳入：wimoor 的写操作批量审核、彩色胶囊按钮风格、渐变横幅。前者违反架构红线，后者是审美倒退。

## 6. 实测方法备注

- wimoor 后端完整启动命令（本次验证通过）：
  - Docker：`wimoor-mysql`(3306,root/123456)、`wimoor-redis`(6380,123456)、`wimoor-nacos`(8848,standalone)
  - Nacos 配置：`init-config/nacos/DEFAULT_GROUP` 12 个配置导入 public，注入 `redis.port=6380`

  - 前端：`wimoor-ui` `npm run dev`(8084)，修复 `upload.vue`→`Upload.vue` 大小写
- wimoor 登录：`admin@wimoor.com / 123456`；woker 本地：`admin@example.com / DzRjBLHzFvJjAQXlLp8Archi`（`npm run db:seed-admin`）
