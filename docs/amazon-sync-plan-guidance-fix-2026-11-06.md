# 同步计划空态修复（2026-11-06）

## 已核实原因

- 本机只读数据库检查确认：已验证授权下存在 37 个数据源和 37 个自动计划，覆盖 catalog、inventory、orders、sales_traffic、finance、returns、settlements、reimbursements、inventory_age、inventory_events。此计数是检查时点的结果，不是成功发布覆盖证明。
- 用户页面选中的是 catalog_items（商品目录），不是 catalog（在线商品）。catalog_items 需要来源策略明确列出的 ASIN；automatic-connection 不会为它自动建立全店来源。listing_details、fulfillment、pricing 同样依赖有界对象策略；brand_analytics 与 buy_box_history 不在 automaticResources 中。
- MCP 数据可用性统计成功发布且可访问的来源，0 个来源不能用于推断数据库完全没有数据源或计划。此前将该面板解释为“未创建计划”的判断不准确。
- Worker 进程存在；日志曾持续报告 heartbeat/recovery failed，后续也出现 completed 日志。不能据此把历史日志判定为当前 Worker 离线，completed 也不等于任务成功发布。当前运行环境修复需另行核实具体持久化任务和心跳。

## 本地变更

- 仅调整 operations 同步计划页面：展示当前工作区可见计划总数、选中域计划数、筛选后数量。
- 有界域明确提示对象/报告周期配置要求，提供跳转在线商品全量计划、数据源授权与后台状态的入口。
- 区分已有计划被筛选隐藏与该域没有计划。
- 新建计划入口只对现有支持自定义计划的 catalog / inventory 开放，其余域与后端限制一致。
- 未修改调度器、权限、来源策略、配置、数据库、迁移或 Worker 进程；未主动请求 Amazon、创建任务、commit/push 或发布。

## 验证与回滚

使用隔离 mock API 的 Playwright 验证计划创建/启停/复制/历史、按域切换、有界目录到在线商品计划的跳转及筛选隐藏后清除恢复，并断言新测试路径没有 POST 操作。三项相关浏览器测试通过；TypeScript 与两份修改源码的 ESLint 通过。未执行完整生产构建或真实全量采集。

回滚只需撤销本次页面与测试 diff；无需数据或配置回滚。若要把 catalog_items 等域扩展为全店自动采集，应先审阅对象发现、分页/预算、权限、性能、持久化及回滚方案，获得明确批准后再实施。

## 待批准的后续实现范围（尚未实施）

本次页面修复不等于补齐全域自动采集。建议下一阶段先离线实现 catalog_items、listing_details、pricing 的全店对象发现：以同组织、工作区、店铺、站点已经完整发布的 catalog 快照发现 ASIN/SKU，按现有上限分批，复用来源策略校验、任务幂等、限流、审计和发布边界；不以缓存或部分快照宣称全量覆盖。缺角色或未完整发布时显示明确阻断原因。

- 影响范围：自动来源发现、调度及对应对象策略；可能增加数据库扫描、任务数与 Amazon API 调用。首次范围较大时同步耗时增加；采取分页、既有限流和可恢复游标，避免全量对象一次性加载。
- 替代方案：继续明确指定对象范围，保留本次准确提示，不扩大调度。
- 验证：仅使用 mock 快照/API，覆盖跨组织隔离、角色不足、空快照/部分快照、超上限分批、重复与断点恢复；共享逻辑按仓库规则运行 check:fast。
- 回滚：停用新增能力并恢复代码；保留历史审计和已发布数据，不自动清理或反向覆盖事实源。具体能力开关与运行配置的引入也须纳入获批方案。
- 授权边界：可先批准离线代码与 mock 验证；真实来源策略写入、启动任务、外部 API、worker 重启、提交推送和部署均不包含在其中，仍须按具体目标与范围单独审阅批准。fulfillment 的全货件发现、品牌分析资格/报告周期及 Buy Box 历史范围需要各自方案，不能虚构为已完成全量同步。
