# 品牌共享令牌公平调度修复方案（已批准并完成本机重载）

## 已核实问题

本机四站品牌报告使用同一 Seller/Application/operation 令牌桶，预算保持 .01 rps。加拿大原任务 5d301276-3ea7-46e2-931f-43402de7fc50 自链接过期后，停在 DOCUMENT 等待；其他站点连续取得 getReportDocument 配额。当前调度按下一次尝试时间重新竞争，没有基于实际调用等待时间的公平性保证。

隔离模拟使用现有 reserveOrderToken：重试周期120秒、某等待者每轮在0秒尝试、另一调用方每轮在25秒尝试、令牌间隔100秒。30轮结果为等待者获准0次，另一方30次。模拟未连接真实数据库/Redis/API。该复现证明有可能长期饥饿，并不证明真实环境所有延迟都只由这一原因造成。

## 拟实施范围

- 仅在品牌观察任务领取共享 operation 令牌前增加公平轮转；其他订单、财务、Listing、Catalog、Ads 等数据域保持原行为。
- 复用 PostgreSQL 任务/日志及当前 seller-operation advisory lock，按同组织/工作区、授权、applicationId、相同操作的有效品牌任务，优先让最近实际请求最早者取得下一次机会；尚未请求者按任务开始时间排队。同一候选需继续通过原权限、source revision、plan revision、租约和预算校验。
- 使用冻结策略和已加密检查点判定原报告阶段，不能通过报告名称新建任务或重新 createReport。只在待执行的相同操作之间轮转，不让未来轮询抢占当前下载。
- 候选读取设置明确上限，批量读取相应操作的最近日志，避免每个候选单独查询；超过安全上限保守停止本次分配并保留任务。新增查询仅限品牌配额竞争路径，可能略增单次调度 SQL 开销，换取避免同站点长期抢不到配额；不增加 Amazon 调用频率/总请求预算。
- 预计文件：src/lib/amazon-sync/processor.ts、品牌公平判定小模块、相关单测和 tests/integration/amazon-observations.integration.ts、当前本地品牌验收文档。无数据库迁移，无配置/凭据修改，无生产发布。
- 本机目标仍为既有根 .env 指定的 amazon_sync_live_local、amazon-live-local/default、授权 revision3、四站固定2026-10-25至31、90任务、原ASIN/请求/行数预算。验证通过后仅由原 manager 优雅重载 amazon-sync 注册子进程；不重启其他Worker、不创建额外消费者。

隔离验证固定重试相位下四站均能取得机会、不同operation/application/授权不相互阻断、成功/取消/失败/暂停任务不抢占配额、原请求预算与不确定create保护继续有效；运行品牌专项集成、相关单测、类型/lint。真实验收重点观察加拿大原任务恢复及四站已发布结果一致，不修改真实任务历史计数。

回滚仅删除品牌公平判定调用并经manager重载同一Worker，恢复原争抢行为；数据库任务、事实、原文、审批记录保留，不恢复数据库、不清空Redis、不回滚已发布数据。公平修复失败时保留原任务并报告，不自动提升速率或修改授权。
