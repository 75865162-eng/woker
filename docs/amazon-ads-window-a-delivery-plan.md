# Amazon Ads 授权与同步层：落地评审

状态：2026-11-06，A1 离线落地已完成，A0/A2–A5 仍为评审方案。输入为下载目录的《01-窗口A-授权与同步层》和《00-协作公约与总览》；附件是需求材料，不是运行命令。本文件不授权真实凭证、外部 API、数据库迁移、任务启动、GitHub 推送或生产发布。

## 问题定性与现状

这是跨授权、数据模型、同步 worker 与外部写入的功能需求，伴随数据一致性和权限风险（P1）。本地工作区存在大量既有未提交改动，以下现状仅指当前工作区，不代表已合并、迁移、部署或真实账号验收：

- `src/lib/amazon-ads/authorization.ts`、`oauth-contract.ts`、`credentials.ts` 已有 Ads 独立 OAuth、单次 state、区域 Profile 发现、加密 refresh token 和绑定；授权表、同步表迁移尚未提交。
- `sync-service.ts`、`sync-scheduler.ts`、`sync-processor.ts` 已有计划、任务、租约和隔离控制。`sync-adapter.ts` 明确未实现，自动调度在 adapter 未就绪时停止。现有计划默认关闭并限制组织/工作区。
- `src/lib/amazon/ads-client.ts` 有 SP v3 出价请求及逐条结果解析，真实 transport 保持 `NOT_IMPLEMENTED`；现有 Agent 审批路径也有写入闸门。
- 当前 `AmazonAdsEntityRecord` 和 `AmazonAdsReportFact` 是按业务键 upsert 的当前值，处理器逐页更新，不能作为只追加原始记录或完整版本发布的证据。已有 Sellfox 报表及 PPC workbook 是独立来源，不能将其伪装为 Ads API 数据。

## 附件对照与决策

| 项目 | 处理建议 |
| --- | --- |
| 独立 OAuth、Profile、状态、密钥加密、断点、限流、日志脱敏 | 接受目标，复用现有 Next.js / Prisma / BullMQ 边界并补足缺口；不复用 SP-API 凭证。 |
| `backend/app/**`、`web/**` 和 `win_a_*.sql` | 仓库没有这些应用目录；沿用 `src/lib/amazon-ads`、App Router、Prisma 时间序列迁移和既有测试，不另造平行后端。窗口白名单及并行分支是附件协作建议，不自行创建窗口或分支。 |
| 四张通用原始表及数仓表 | 不重复创建已有授权、计划、任务表。原始记录应按 tenant/profile/run/版本不可变保存，现有当前值仅作可重建投影；存储方案与查询契约需另审，不能宣称现有表已满足。 |
| “原始表只写不覆盖”与 D+4 “修正覆盖” | 保留每次报告版本，修正生成新版本；仅在完整校验及权限复核后原子发布最新版本，旧版本可追溯，失败版本不可见。 |
| 全量一律 Exports、固定端点与固定日期/配额 | 作为待核验假设。按广告产品、区域、权限及 API 版本核对官方操作、请求/响应、分页/异步状态、下载有效期、保留期、归因延迟、429 行为；未证实前不实施或开启 adapter。v1 与 v3 不能混淆指标口径。 |
| 首次固定 95/65 天、D-1 与 D+4 | 仅作候选策略，按具体报表的官方可用范围、Profile 时区、归因窗口与上游修订周期决定。`D+4` 不能默认代表转化已最终稳定；现有调度使用 UTC，需先修正业务日语义。 |
| refresh token 365 天、60/30/7 天提示 | 已按服务端记录的到期日提供浏览器安全的 60/30/7 天及已过期站内提示，并在过期时保持同步阻断；缺少或无效到期时间明确显示为未知，不伪造期限。实现不声称 Amazon 已撤销旧 token；重授权通过授权 revision 围栏旧任务。365 天适用范围和签发时间语义仍需继续以官方契约核验。 |
| 写客户端“不做业务校验” | 不移除现有批次、身份、字段和响应安全校验。网关负责权限、审批、业务与变更前后核对，客户端负责协议校验和逐条结果；超时、缺结果或 5xx 视为结果未知，先核对再处理，禁止盲目重试。真实写 transport 仍保持关闭。 |
| `GET /api/sync/health` 和固定表/API/MCP 契约 | 附件公约的跨窗口契约尚未与现有路由、权限和消费方对齐；先出兼容合同，不在本轮擅自替换现有接口或将 SP-API 的自动同步授权扩展至 Ads。 |

## 分阶段实施清单

1. **A0 合同核验**：为每项能力建立官方来源、版本、账户资格、响应示例与限制清单；冻结实体及日报的粒度、金额精度、站点时区、归因与失败语义，准备脱敏 fixture。未核验的能力仍标记不可用。确认本地未提交迁移的依赖关系及是否已有环境应用，避免改写已应用迁移。
2. **A1 授权完善（已完成本轮离线部分）**：账户页按数据库记录的估算到期日显示 60/30/7 天、已过期及到期日未知提示；同步服务在到期或 revision 变化时阻断。纯日期逻辑位于浏览器安全模块并有边界测试。重新授权的上游撤权语义仍未宣称，真实配置和传输未启用。
3. **A2 原始层合同**：评审不可变原始记录与可重建投影、任务状态及完整发布边界；给出 Prisma 增量迁移、保留策略、密钥/原文访问边界和存储容量预算。按 organization/workspace/profile/run 关联，重试幂等且冲突拒绝，历史修正可追溯。不读取或回填真实数据。
4. **A3 读取 adapter**：分资源实现已核验的导出或报告有界状态机，明确创建结果不确定时的核对策略、URL 过期恢复、解压及响应大小限制、检查点和完整发布；报告版本保留精确金额与归因。使用 fixture 验证中断、重复投递、429、失败和旧版本可读。
5. **A4 调度与健康度**：复用任务/全局 client 限流和现有队列，在 Profile 时区按已确认策略分批安排回补及修正；按资源报告新鲜度、来源和完整性，保留显式 scope、授权 revision 与租约围栏。默认关闭，监控只暴露非敏感字段。
6. **A5 写入接口合同**：复用现有客户端和审批网关，先做 mock-only 协议及部分成功/未知结果测试；定义版本、幂等、核对及逐项审计。真实写入 transport、变更单扩展及其权限模型需独立设计和批准。

各阶段完成前更新本文件对应证据、可复现命令和剩余风险；A2/A3 未完成前不得宣称数据已同步或打开读取闸门。A1 本轮离线验证运行 `node --import tsx --test tests/amazon-ads-sync.test.ts`（8 项通过），并运行 `npx tsc --noEmit` 与 `git diff --check`。

## 验证、性能与回滚

- 授权纯逻辑与协议：使用注入 transport 的隔离单测，覆盖区域、state、有效期边界、密钥隔离、重授权身份及脱敏。UI 和 DTO 变更按风险做类型检查和对应模拟浏览器测试。
- 原始层与调度：临时 PostgreSQL/Redis 和 mock HTTP 验证实际迁移、tenant 权限、并发 fence、逐页恢复、原始不可变、完整发布、修订及失败恢复；不加载真实 dotenv，不运行真实 worker。涉及共享 API/worker/schema 时做对应专项及 `npm run check:fast`；合码前再做完整 `npm run check` 和 `git diff --check`。
- 不可变快照、回补和报表解压会增加存储、数据库写入、队列请求和 CPU/内存；先给出估算、限额及 mock 压测指标，评审后再决定策略，不能承诺生产 P95。替代方案是缩短回补窗口、降低频率、限制并发及原件存储期限；任何清理真实数据需单独批准。
- 代码回滚应先保持 adapter 和调度关闭，保留已写入版本及审计；已应用 schema 只采用经评审的向前兼容修复，不自动删表或回滚数据库。关闭功能不撤销 Amazon 端授权；真实撤权另行批准。

## 需要确认

仓库 `AGENTS.md` 要求对共享数据模型、权限、API、worker、存储边界及可能的性能影响先说明范围、回滚和验证并取得确认。本轮已在不连接真实 Amazon、不操作真实配置或数据库的前提下完成 A1 的离线实现和测试。A0 合同核验仍需补证据；A2 的存储设计、A3/A4 的同步能力及 A5 的写入能力分别评审，任何真实迁移、配置、联调和发布仍须针对具体目标单独批准。

### 已识别的不合理或冲突要求

- 附件要求的 `backend/app/**`、`web/**`、`win_a_*.sql` 不属于本仓库结构；继续创建平行后端会破坏现有 Next.js / Prisma / App Router 边界。
- “原始表只写不覆盖”与“D+4 修正覆盖”不能同时按字面实现。应追加新报告版本，再原子发布经过完整校验的最新版本，保留旧版本追溯。
- 附件中的四张通用原始表不能直接替代现有 `AmazonAdsEntityRecord` / `AmazonAdsReportFact`。现有记录是业务键 upsert 的当前投影，不具备不可变原始层语义。
- “写客户端不做业务校验”不能删除现有服务端身份、权限、审批、批次、字段和结果安全校验；客户端只能不重复业务决策，不能绕过协议和安全校验。
- “全量一律 Exports、95/65 天回补、D-1/D+4、365 天 refresh token”目前只能作为待核验假设，不能直接开启任务或迁移。尤其 365 天规则的适用范围、签发时间和历史凭证未知日期尚未得到本地证据确认。
- 附件与现有边界均要求保持 SP-API 独立；本计划只处理 Ads，不改动既有 SP-API 实现。

### A2 待审批设计草案

建议新增不可变版本清单和原始分片两个概念，继续复用现有同步任务、授权和当前值表，不重复创建凭证或任务表：

- 版本清单按 organization、workspace、profile、资源类型、业务日期或快照范围以及来源任务关联，记录 API 版本、请求口径、状态、校验摘要和发布时间；同一发布范围只有一个当前版本。版本从接收、校验到发布单向推进，失败版本不可见。
- 原始分片以版本 ID 和分片序号为唯一键，保存经过大小限制和脱敏检查的原始载荷或受控 storage 对象引用及摘要；重复写入须校验摘要一致，冲突则拒绝。具体使用数据库 JSON 还是对象存储，须先按样本大小和吞吐 benchmark 确定，不能预设永久保存期限。
- 发布时在事务内复核组织、Profile、授权 revision、租约和完整性，再切换当前版本指针；当前 `AmazonAdsEntityRecord` / `AmazonAdsReportFact` 保持可重建投影。需要明确投影重建期间的读取策略，不能把逐页更新误称原子发布。
- 增量 Prisma migration 只新增结构及必要索引，不重写既有迁移、不自动回填。原始载荷访问限服务端授权角色，日志不记录 token、下载 URL 或原始响应。保留期、清理权限和数据删除另行审批。
- 容量评估使用 `Profile 数 × 每日资源版本数 × 每版本压缩后字节数 × 保留天数`，并单列索引、投影和重建峰值；在缺少实际样本前不承诺容量或 P95。可先用合成样本测写入、重建、查询和并发，按结果选择分片上限及频率。
- 回滚先关闭读取 adapter 和调度，保留已写入版本及审计，切回旧读取路径；已应用 schema 不自动删表。验证使用隔离 PostgreSQL/Redis 和 mock 数据，覆盖租户隔离、重复投递、摘要冲突、中断恢复、旧版本可读、原子发布和重建一致性。

该草案尚不授权修改 schema、执行迁移或访问真实数据；A0 合同与容量测试结果可能改变最终设计。
