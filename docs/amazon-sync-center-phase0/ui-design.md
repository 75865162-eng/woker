# 页面信息架构与交互规格

## 1. 导航及兼容入口

保留全局 `/operations`「经营中台」，本区标题为「Amazon 数据同步中心」。左侧是七个同步中心入口；原库存、在线商品、补货、PPC以“业务工作台”快捷入口保留，不删除或移到不可达位置。

| 页面 | 建议URL（待实施） | 旧入口兼容 |
| --- | --- | --- |
| 数据总览 | `/operations?tab=overview` | 原overview保持 |
| 同步计划 | `/operations?tab=plans&domain=inventory` | 原tab=sync映射到plans，提供原手动同步入口 |
| 同步任务 | `/operations?tab=runs`，详情`&taskId=…` | 原runs保留 |
| 数据域管理 | `/operations?tab=domains`，详情`&domain=…` | 原inventory/catalog仍是数据浏览页；不是强制跳规划详情 |
| 数据质量 | `/operations?tab=quality` | 新增 |
| 店铺与授权 | `/operations?tab=connections` | 复用设置中的集成入口，敏感编辑仍settings:edit |
| 同步设置 | `/operations?tab=sync-settings` | 不替代全局AI设置 |

现有页面用query tab；Phase1先延用以减少路由改动。刷新/前进后退还原当前页、域、筛选、taskId；不在URL放密钥或分页token。顶部组织/工作区由既有app shell管理，中心内店铺、站点筛选为本区范围；后端须实际应用过滤，不能只改页面标签。

## 2. 视觉和通用交互

紧凑工具型SaaS，沿用globals.css的brand #176b87、边界、中文字体和现有Button/Card/Badge，lucide图标。七页共享192px左右局部导航、紧凑标题栏、店铺/站点筛选、来源与asOf；桌面主区表格优先。原型采用近似产品语义样式，不进入应用组件代码。窄屏导航换行、过滤纵向、表格局部横滚，避免全页面横向溢出。

所有页区分：loading骨架、error带重试、无权限、未配置、首次未同步、真实空快照、规划中、授权不足、源数据延迟、过期、部分可用。缺失值显示“—/未知”，不补0；成功空快照必须显示“成功 · 0条”及覆盖证明。颜色配文字，不仅靠红绿；键盘可达、label关联、进度读屏、保存提示aria-live。

交互原型顶部常驻“Phase 0 · 演示数据 · 不执行同步”，页面中的保存/立即执行/重试均仅更新本地预览状态，并明确反馈；无网络请求、无真实凭证输入。规划中域禁用同步和启用计划，仍可查看未来配置形态。评审原型不作为业务功能完成证明。

## 3. 数据总览

布局：标题/店铺＋站点 → 六个紧凑指标 → 全宽域健康表 → 24小时趋势＋异常列表。健康表列：域、适配状态、最近成功、覆盖范围、当前任务状态、下次同步；点击域进详情，异常进任务或授权详情。

指标定义（均按当前org/workspace/店铺/站点筛选、同一asOf计算）：

- 已连接店铺：当前筛选下具有可用授权的去重SellerAccount数，不按站点重复计。
- 已启用域：至少一个有效启用计划的已实现域去重数；不包含规划中与仅配置声明。
- 运行任务：RUNNING任务数，不含QUEUED/等待报告释放槽位的任务；等待另显示。
- 同步异常：未解决同步incident/task失败/授权问题去重数，非把每次重试累加。
- 过期域：已实现且有新鲜度规则的scope-domain数量；同时标明“作用域数”，不能混称不同域数。无数据与规划中不计过期。
- 最近成功：已发布同步任务最大finishedAt，不包含readiness验证。

趋势服务端按小时聚合24小时成功/失败计数，执行耗时P50/P95和429次数分别独立量纲，不能用前端最近20条推全貌。排队延迟、报告等待分别列，数据缺失显示未采集。异常排序：权限/授权阻断、持续失败、过期/缺数据、限流；限流后恢复也保留事件但不冒充当前故障。

## 4. 同步计划

左侧按商品库存/订单经营/财务售后/价格竞争/品牌分析分组域，显示已接入/规划中。右侧计划列表与编辑面板；一域可有实时、回填、全量校准多个计划。当前scope对应明确店铺站点目标，目标变更保存前显示展开任务数量与请求/容量预估。

字段：名称、启用、模式、15/30分钟/1/6小时/每日/自定义周期、IANA时区、起始/截止范围、目标店铺/站点、P0–P3、最大重试/指数退避/jitter/最大间隔、stale阈值、历史/原始文件保留。报表域额外显示日期粒度、数据日期、延迟容忍、7天等回查窗、重申请/缺日补偿。非法组合禁保存，错误贴字段；乐观并发revision冲突提示重新加载比较，不覆盖别人计划。

操作：新建、编辑、复制（默认停用）、暂停/恢复（只影响未来任务）、立即执行（创建task后导航详情）、执行历史。改变正在运行任务的计划只影响未来，运行任务展示旧planVersion。立即执行先preview范围/预估，计划未保存时先明确使用哪个版本。没有edit权限只读；create控制触发任务，settings:edit控制授权编辑。规划中域可浏览形态但不能启用执行。

## 5. 同步任务

顶部店铺/站点/域/类型/状态/时间筛选；服务端分页、稳定排序（时间＋ID）。状态七类；BLOCKED/RETRY_WAIT/PAUSED以等待＋原因说明并可筛选。行包含ID、域、店铺站点、触发方式/模式、阶段、状态、开始、耗时、记录数、下一重试。点击展开页内详情，不因筛选刷新丢失。

详情：身份及来源、planVersion、父/子scope、queuedAt/真实开始/结束、排队/运行/报告等待时长、处理/新增/更新/跳过、请求/429/attempt、分页与checkpoint（不露token）、coverage、结构日志、错误码及建议。总页数未知时写“已处理n页/总页数未知”，不能伪造百分比。报告阶段进度分开显示远端状态、本地阶段及下一探测时间。

失败重试：同scope失败片段新attempt并保留历史；部分成功仅补失败scope；取消合作式停止；暂停恢复保留checkpoint。操作返回202只显示已创建/排队，不能立即显示完成。队列completed与DB状态不一致展示异常并自动修复/告警，UI仍以DB为准。

## 6. 数据域管理

全域表显示分类、来源、接入状态、授权检测、最近覆盖、策略。商品库存：在线商品/FBA/FBM/在途；订单经营：订单/订单行/销售流量；财务售后：财务/结算/退货/赔偿/库龄；价格竞争：价格/Featured Offer；品牌：搜索词/品牌分析。

域详情固定展示：说明、已核API版本或报告候选、当前核验状态、所需授权（未核实明确待核）、支持站点（仅实测）、范围、最近成功、coverage、条数、计划/保留、质量/最近任务及业务读取入口。未接入域为规划中，条数和成功时间为—；不因为存在默认频率或mock任务而显示已接入。

保留在线商品列表、库存浏览入口和商品主档只读校准说明。FBA库存与在途货件分开，不将available/inbound汇总称货件详情。

## 7. 数据质量

问题列表：严重度/类型、店铺/站点/域、发现和最近发生时间、受影响日期/SKU/页/条数、状态、建议动作；筛选打开/已知悉/已解决。点击详情看rule版本、关联task/manifest、证据摘要与补偿范围，含敏感字段的样本不返回。

规则分层：新鲜度与源延迟、分页完整/循环、报告下载/解析/coverage、业务键重复、关键字段缺失、订单更新滞后、库存异常跳变、对账偏差。授权问题独立呈现。检查任务也后台执行，不在页面加载时扫全表。已知悉只影响处理标记，不使数据变新鲜/完整；修复后重检才解决。Phase1只实现库存/刊登基础规则与新鲜度，Phase4完成独立质量中心，不提前显示全套已上线。

## 8. 店铺与授权

上方授权连接列表（Seller身份/区域/凭证版本状态/最近验证/覆盖站点），下方ERP店铺绑定与已实测域能力。添加授权引导：选seller/region→受控凭证或未来OAuth→验证参与站点→绑定active ERP店铺→逐域能力检测→保存默认停用计划。OAuth不宣称现有已实现。

只读operations:view只能看安全状态摘要；settings:edit才可打开现有敏感设置。密码不回填、不回显，空输入保留密钥，主密钥轮换另行受控。修改授权后连接需重新验证，关联等待任务展示授权版本冲突。解除绑定先展示关联计划/活动任务，再停用/取消安全处理，不删除历史事实。

## 9. 同步设置

分组：Worker与队列心跳/延迟、调度时区及默认stale、并发预算与重试上限、日志/原始文件保留、告警/通知预留、安全策略摘要。实际生效策略区分系统上限/组织默认/计划覆盖；不能由普通页面随意改进程env或开全局高并发。实时quota/429影响预算可读，未采集显示—。

会影响性能、全局权限/并发/保留清理的配置保存前需显示范围、容量、回滚与验证；没有已实现API的设置禁保存并标规划。通知渠道未配置时明确待配置，不虚构已送达。

## 10. 原型评审走查

`prototype.html`支持七页切换、店铺站点筛选、域选择、计划字段联动/校验、保存/暂停/复制/新建/立即执行的本地模拟、任务过滤/详情/重试、质量问题展开、授权及设置页。两已接入域与规划域明确区分；报告任务仅为未来状态演示，与现状能力标签区分。

建议评审路径：总览→失败异常→任务详情→重试；计划→在线商品→修改频率→保存→暂停/恢复→复制；域管理→销售流量规划详情→检查报表配置形态；筛选店铺/站点后确认列表范围；质量→分页不完整证据；店铺授权→确认多凭证/旧设置关系。以上均不产生真实任务。
