# Amazon 自动同步

## 2026-11-11 Finance 独立历史补采（本地，未发布）

Finance 自动计划在前向水位已成功的情况下，扫描当前来源和授权身份下已完成、分页完整、`transportComplete=true` 且无隔离行的窗口证据；只补已覆盖区间之间的内部缺口。查询范围从 Finance 两年滚动保留期边界后一天开始，给排队留出余量；连续未覆盖前缀仍交给既有前向游标，Amazon 不再可查询的历史也不会被宣称为完整。超过 10,000 条证据时规划失败关闭，不截断后继续补采。

补采任务由自动计划创建并冻结窗口。分页 token 保存在任务检查点中；Worker 复用 Finance 传输、原件归档、解析、幂等入库和发布路径。成功后只递增财务记录观察序号并写入该任务覆盖证据，不回退或改写共享前向水位、共享分页 token、活跃任务及来源最新成功状态。旧版本任务、身份/策略不匹配窗口和已超出成功水位的窗口会被拒绝；共享 Finance 游标尚未成功时仍按原任务恢复。

隔离 PostgreSQL/Redis 自动同步集成 24/24 通过。新增场景在已有前后完整窗口和已推进游标之间制造缺口，通过自动排程及真实本地 Worker 调用模拟 Finance HTTP 响应，验证任务成功、财务记录发布、前向水位/任务/token/status 不变、观察序号递增，以及下一次排程恢复普通前向增量。Finance 历史规划单测和类型检查、相关 lint 在本轮最终回归结果中记录。未调用真实 Amazon，未连接生产队列或生产数据库，未提交、推送或部署。回退应用逻辑即可停止新补采规划；保留任务、原件和已发布财务记录。该能力只覆盖 Finance 内部历史缺口，不代表 Orders、Returns 等其他游标域已支持任意历史重放。

## 2026-11-10 日期报告历史缺口修复与滚动复查（本地，未发布）

日期窗口策略新增 `automatic-day-windows.ts`，由适配器 `dayWindows` 声明历史目标、单次上限、近期复查天数和完整性证据要求；规划入口继续通过 `planTask` 回调调用现有调度、Worker、归档和发布流程，没有新增调度系统。`automatic-day-history.ts` 在数据库端合并所有符合条件的成功窗口，不按最近任务条数截断；读取绑定租户、来源、资源、冻结身份、授权历史规则及完整性标记。非法日期、错误账号/站点、不完整归属和库存单事件筛选均不能填补缺口。`sales-history.ts` 复用该仓库读取。

- 销售流量：730 天目标、每份至多 31 天；先补最早内部缺口，追平后每个原有调度周期以一份报告复查最近 7 个闭合日，按站点报告时区计算。请求频率和任务并发不变，但近期报告从 1 日扩大为 7 日，解析及归档数据量相应增加。
- 库存事件：540 天目标、每份至多 31 天，仅全事件且传输/归属完整窗口作为覆盖；追平后等待新闭合日，不重复刷新已完整日期。
- 赔偿：730 天目标、每份至多 30 天，要求传输/归属完整；追平后保持原有昨天刷新策略。
- 未完成游标优先续跑原冻结窗口，不因历史缺口重选日期或改变原件身份；已完成游标不再被当作全量历史完整的证明。缺口在下一个已完整区间前截断，避免重复补采该区间。保留原有幂等、版本与发布门禁。

上述天数是现有适配器的请求目标和限制，不能证明 Amazon 实际保留全部历史或真实账号具备资格。Orders/Finance/Returns 继续使用各自游标与质量边界，本次没有承诺任意历史窗口重放；快照型 API 不据此重建历史快照。新增 API 除适配器登记外仍须实现其真实传输、解析、业务存储及发布合同。

## 2026-11-10 适配器声明计划初始化（本地，未发布）

- 卖家级仅归档策略以 `ARCHIVED_SITE_PENDING` 质量状态记录原件已保存、解析行数、站点发布为 0、且当前不可发布；该任务终态成功仅代表归档完成，覆盖仍不计为站点事实成功。
- 执行器进入失败或退避重试时，任务摘要与仍由该任务拥有的数据源覆盖保存 `latestQualityAttempt`：错误代码、原始页数、已处理/插入行数、是否重试及未发布状态。覆盖更新受 `activeRunId` 限制，旧任务不能覆盖新版本状态。

## 窗口、持久化与恢复

SP-API OAuth 回调完成凭证交换、站点与 Seller 身份验证并提交授权后，以及手动凭证验证审批应用成功后，后端都会针对该授权立即调用同一个初始化入口：在数据库中幂等补齐合格数据源、自动计划和首批 `WAITING` 同步任务，再尝试投递 Redis。该路径不依赖用户再点“同步”或等待下一次 30 秒 tick；仍受 `AMAZON_SYNC_CENTER_SCOPES` 精确组织／工作区范围限制。未启用的 scope、非支持站点或初始化异常会返回明确的 deferred 状态，不将空数据标记为成功。

数据库任务行是投递意图的持久化依据。Redis 投递失败时任务保留在数据库；Redis／Worker 恢复后，Worker 的启动和 30 秒恢复扫描会重新投递。此恢复依赖数据库可用、scope 仍启用、标准 Worker 已运行且 Redis 可连接；这次改动未改变服务器进程管理配置，也未验证生产运行状态。

调度器为每来源创建唯一 `auto-v1:<sourceId>` 计划，幂等 ID 和目标关系在同一作用域锁事务中提交。管理员必须仍为组织 owner/database_admin 并具备 create/approve 权限；计划创建有审计。停用的已有自动计划不会被扫描重新启用。

首次自动计划将订单／财务／退货策略起点固定为计划创建时刻前 730 天，并递增数据源 revision；订单每个任务最多 1 天，财务与退货最多 30 天。订单详情沿用来源策略中的详情选项与独立预算。退货报告表示 FBA 仓库已接收退货，不代表所有退货渠道或完整退货全集。新域通过已生成自动计划启停；不允许创建额外自定义计划，计划范围和频率不可改。来源绑定所需的对象清单由既有审批策略提供，不自动发现店铺商品全集。

FBA 库存事件最多回看 540 天，每个报告最多 31 个闭合日期；失败重试原窗口，成功后推进下一段。结算报告 `getReports` 的创建时间过滤最多 90 天，计划只做最近 90 天滚动发现，不声称结算行具有 730 天覆盖。日报按已成功完整报告的日期覆盖计算下一缺口，每次最多 31 个已闭合业务日，目标为最多 730 天；Amazon 实际保留和资格限制可能缩短覆盖。

日报按已成功完整报告的日期覆盖计算下一缺口，每次最多 31 个已闭合业务日，从当日业务日期前 730 天到昨天；仅成功完整报告推进覆盖，失败或部分成功不会冒充完成。API 历史保留和资格限制仍可能导致不足 730 天，不能承诺 Amazon 一定返回全部历史。当前快照仅有在线商品和库存现状，没有历史快照重建。

冻结官方模型为 src/data/amazon-contracts/promotions_2025-12-01.json，下载来源/Blob SHA/内容SHA-256见同目录provenance文件；三个官方操作也登记到已有官方Schema目录。searchPromotions使用单站点、revision=ANY、ISSUES/CUSTOMER_SEGMENTS、每页100；每次保持原参数直到nextToken消失，包括空页。逐促销读取getPromotion的ISSUES/SELECTION/CUSTOMER_SEGMENTS，分别遍历发布与最新修订及购买条件Selection；ITEMS用getSelection及其revisionId翻页，CATALOG保留规则/排除商品，不假装能枚举全目录。先核对搜索摘要与详情的身份、状态、时间及日程一致，最后再次读取详情核验修订未变化，变化则不发布本轮。响应数字保留精确字符串，未知业务字段/嵌套/null保留，原始响应加密留档；公开结果沿用固定秘密剔除规则。事实保留原件任务/页号。

支持BASKET_BUILDING、DEAL、PRICE_DISCOUNT、COUPON和PROCESSING、UPCOMING、RUNNING、EXPIRED、FAILED、CANCELLING、CANCELLED。保存官方提供的schedule、selection、benefit、purchaseRequirements、budget、customerSegments、issues、merchandising、couponType、feeSnapshot、ASIN/SKU及商品级benefit/budget/issues。feeSnapshot.previewedFeeRates是创建时锁定的费率快照（upfrontFee、variableFee及cap），不是实际花费、促销销量或费用账单；本适配器未虚构实际花费。INDIVIDUAL claim code内容及CATALOG商品枚举以官方操作限制为准。

历史范围只声明Amazon实际可见范围，不假设730天或无限期保留。totalResults与实际发现数量不一致、令牌循环、跨站点响应、Selection revision不符、详情变旧或分页中修订变化均拒绝新发布，保留旧头。Amazon以后不再返回的促销保留原事实，标记observation.currentDiscovery=false与最后实际采集时间，不能解释为当前仍在运行或已删除。历史完整性始终为false，累计保留超过行数预算时阻断，不静默丢历史。

增量策略采用每轮完整摘要发现后比较lastUpdatedDate、status与整个摘要；运行中、近期30天及发生变化的对象重新获取详情/商品；超过30天的未变化终态对象可复用同来源/授权下已完整发布的详情与商品，保留原采集时间，最多7天后强制重新读取。官方提供updateDateAfter/updateDateBefore，但当前不以更新时间窄窗代替全量摘要核对，避免遗漏状态和历史缺口；不是纯更新时间游标模式。每操作默认0.1rps、burst1，最多1000次请求/50000事实行、单响应4MiB；超限保留旧版本。解析/入库异常可复用同请求路径摘要绑定的原件，通用数据库/Worker瞬态恢复沿原任务推进，不重复从第一页采集。

来源发现要求已验证Seller身份、适用Marketplace参与、Pricing或Product Listing角色证据；证据不证明实际API资格，实际读取403仍由通用失败规则阻断。官方文档站本轮返回Cloudflare，角色采用用户指定要求，实际角色与站点适用性尚须云端真实只读验收；不能把隔离模拟成功外推为Amazon资格。自动站点范围沿现有automaticMarketplaces，不新增未经核实的站点名单。
