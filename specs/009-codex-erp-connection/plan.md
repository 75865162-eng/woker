# 实施计划

关联：[spec.md](spec.md)。沿用现有 MCP Route Handler、个人凭证与实时数据访问服务，不引入新认证层或数据模型。

1. middleware 仅对精确 `/api/mcp/amazon` 放行到 Route Handler；Bearer 认证保持必需。
2. 补充 middleware 邻接路径回归，以及 middleware 与真实 Route Handler 串联的隔离数据库测试；沿用既有撤权和 Ads 隔离套件。
3. 补齐隔离测试清单中缺失的已有迁移，不触碰真实数据库。
4. 交付仓库 Skill 和脱敏连接步骤，保留旧客户端配置以便独立核对与回滚。
5. 经批准后走 ERP 原审批流程授予单店单站点只读范围，用户受控保存个人凭证，配置客户端并重新发现工具，然后真实读取验收。

影响：认证入口的精确路径分流；不增加查询或数据扫描，无新增依赖。回滚撤回该分流；真实连接回滚撤销凭证并删除新增客户端项，必要时撤回该用户范围授权。

验证采用相关单元测试、SP/Ads 隔离集成、定向 lint 与全项目 TypeScript；完整构建和生产检查在准备合码/上线时执行。既有工作区无关改动保留，未 commit/push。
