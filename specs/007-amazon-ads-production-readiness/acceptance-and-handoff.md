# 分阶段验收、可观测性与交接

日期：2026-11-06。状态：验收设计，不表示已执行、已测得或已部署。沿用 [实施计划](plan.md) 的性能候选门槛。

## 发布门槛

| 关口 | 必需证据 | 阻断项 |
| --- | --- | --- |
| R1 离线可恢复 | 合同状态、Raw/文件完整性、实际队列恢复、权限/取消负例、DC案例、基线兼容 | 重复创建/发布、无界读取、scope漂移、错误完整性声明 |
| R2 真实只读试点 | 精确审批单、真实采集来源、同口径对账、请求/容量消耗与停止恢复记录 | 未决账号身份/合同、未知目标或超预算；fixture不得替代真实证据 |
| R3 可信草稿 | SP场景数据完整、结构历史、策略与证据版本、US4路径、BS/CL适用案例 | 对象映射不可信、null当0、过期/未成熟证据被用于可执行动作 |
| R4 单操作执行 | 正式合同、服务端实时权限、精确审批、逐项执行/回读、未知结果对账、故障演练 | 盲重试、整批伪成功、批准与执行内容漂移、无逆向草稿边界 |

每个关口单独登记“通过/有条件通过/未通过/未验证”。有条件通过必须列限制并从产品能力中排除受限部分；P0数据/权限风险不允许真实启用。测试通过数只作辅助，不能替代关口证据。

## 验证方法和证据格式

报告运行故障注入采用[RT01–RT10](report-runtime-design.md)，与DC数据口径、BS业务路径和CL执行案例分别记录，不用一个总测试数替代分项验收。

- 纯函数：字段/身份规范化、digest、金额精度、零/null、比率、重复/冲突与过期；避免测试只复制实现。
- 隔离集成：一次性PG/Redis、临时storage、mock transport、网络保护；真实队列重复dispatch、进程终止、存储/事务失败和权限竞态。
- 页面：现有入口至详情/诊断/草稿/审批路径可达；UI/MCP同筛选与版本结果一致；保留Demo和旧Bulk路径。
- 性能：记录代码SHA、数据种子/规模、硬件/数据库版本、并发、预热、请求数、错误率、P50/P95/P99、峰值RSS和SQL计划。网络等待与解析/数据库耗时分开，不把mock吞吐当Amazon吞吐。
- 真实核验：仅在获批范围执行，记录上游口径、时区、生成/查询时间、抽样选择及容差。不同生成时间导致的归因变化记录为待解释差异，不能放宽容差掩盖。

交付记录模板：任务ID → 文件/接口/模型diff → 风险与授权范围 → 命令及输出摘要 → 结果/失败原因 → 未覆盖项 → 回滚入口 → 下一批依赖。记录时间、代码版本和证据路径，不包含密钥、下载URL或业务原文。

## 观测与响应设计

| 信号 | 必需维度 | 响应边界 |
| --- | --- | --- |
| 最后尝试/成功、覆盖/成熟状态 | 组织/工作区/Profile/域/合同 | freshness不能代替覆盖；失败保留旧成功时间 |
| create/poll/download/refresh次数、剩余预算 | 任务/attempt/operation | 越预算停止新请求，不自动扩窗加额度 |
| 文件/hash失败、孤立对象数量/字节 | 任务/文档/受控对象引用 | 不发布；记录待处理，不自动删除 |
| 排队时长、lease过期、重试、429/5xx | 队列/阶段/任务 | 有界退避与恢复；未知create进入对账 |
| 未知执行、回读不符、批准过期 | 单项执行/对象/审批摘要 | 暂停该对象后续写入，人工审阅；不继续自动化 |
| SQL/请求P95、RSS、磁盘增长 | 环境/版本/规模 | 达候选门槛时停止扩大试点并评审；不自动清理数据或新增缓存 |

告警阈值、接收者、通知渠道及值班人待目标环境确认；本轮不建立自动通知或向任何人发消息。日志默认安全错误码和trace/task IDs，高基数明细进受控审计，不将Raw/签名URL放指标label。

## 交付中的角色与责任

业务负责人确认口径/策略/可接受风险；合同核验人给官方证据；开发者实现与隔离验证；审阅者核对范围/diff/迁移/性能；获授权执行者仅执行批准操作。具体人员尚未指定，不假设已有SRE/独立团队；同一人兼任时仍保留各步记录与适用审批政策。

保持单一任务状态索引：24项任务清单是执行索引，专门交付文档是完成证据。其他聊天的新增代码不因存在文件即认定通过；不重复勾选，也不覆盖已有完成状态。当前工作区T05已标完成，本轮不重新运行或替其证明storage专项结果。

## 回滚和运维演练

先在隔离环境演练停止调度、取消未发送项、旧fence拒绝提交、恢复原读路径和保留历史版本。生产发布只在明确要求后使用CI artifact；数据库只前向修复，广告远端变更通过新审批逆向草稿处理。恢复后检查版本和任务仍可追溯，不用删记录制造干净状态。

保留期、密钥轮换、组织关闭、撤权后Raw访问、孤立对象处理应在R2前形成范围明确的方案；任何真实删除/密钥配置修改另行批准。事故首要动作是停止扩大影响并保存证据，不自动重跑同步/写入或回滚数据库。
