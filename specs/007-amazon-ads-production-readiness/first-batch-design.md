## 当前基线补记

## T02 正式版本决策记录

产物为单独 ADR；本文件不提前作最终版本选择。官方信息沿用 U1 交付记录，仅作历史证据；本轮未重新在线核验，待 T02 核查公共官方文档后填写来源和核验时间。

| 选项 | 能复用的部分 | 决定前必须核实 | 允许进入正式实现的条件 |
| --- | --- | --- | --- |
| V1 | 已有通用合同基础、存储/发布/查询边界 | advertiserAccountId 权威映射、目标区域/角色、字段/日期/归因、下载/多文件、限流与未知创建处理 | 所需字段及身份可证明；完成 fixture；审批范围精确 |
| V3 过渡 | 已有 Campaign 子集 parser 和离线 acquisition | 当前可用性、历史记录中的停用时间、身份/header、覆盖及空值、下载策略 | 明确迁移退出里程碑与成本，正式启用前留出迁移验收时间；不能因复用方便忽略生命周期 |
| 暂缓正式采集 | 保留只读结构和离线开发 | 补证负责人/资料路径 | 任一关键合同无法确认时采用，不开放真实任务 |

ADR 必填：决策ID、状态、来源/核验时间、适用账号类型/区域、字段清单、身份映射证据、日期/时区/覆盖、配额与运行策略区分、替代方案、迁移成本、退出条件、批准范围、未决项。不将账号权限写成文档已证明，不要求提供密钥。

### T02 补证执行清单

本表定义怎样完成补证，不表示本轮已重新核验官方文档。证据状态分别使用“未核验/官方已核验/存在冲突/目标账号未验证/目标账号已验证”；公共文档核验和账号验收可同时处于不同状态。

| 证据ID | 必须回答的问题 | 取得方式与成果 | 不能据此推断 |
| --- | --- | --- | --- |
| CE01 | V1/V3当前生命周期、区域和账号类型限制是什么 | 只读官方指南/参考/变更日志，记录URL、版本、核验日期、原结论摘要及冲突 | 文档可用不证明账号有权限 |
| CE02 | create/retrieve/poll的真实端点、请求头和身份字段是什么 | 官方schema与示例交叉核对；分别记录内部Profile、Amazon Profile、advertiserAccountId映射来源 | 不能从ID形似数字或同一授权推导等价 |
| CE03 | Campaign日报可请求哪些维度/指标组合 | 官方字段/维度兼容表，形成最小请求与响应fixture；标必填、可缺失、nullable及类型 | 不用其他报表字段替代当前报告 |
| CE04 | 日期范围、历史、时区和点击/转化日语义是什么 | 指定报告/版本的官方说明；区分请求上限与历史保留，登记不明确项 | 当前Profile时区不证明历史报告时区 |
| CE05 | 归因窗口、迟到修订与成熟策略有何依据 | 官方指标定义；成熟策略单独记业务假设、版本和限制 | 不把7d归因直接当7天后永久最终值 |
| CE06 | 零行、缺日、缺对象与warning意味着什么 | 官方保证、反例及适用过滤条件；对应DC02/DC03/DC13裁决 | 不用空数组或MIN/MAX证明完整性 |
| CE07 | 远端创建幂等、重复请求、超时未知结果怎样处理 | 官方错误码/查重或检索能力证据；无能力则记录人工对账路径 | 不因HTTP失败认定未创建 |
| CE08 | 文件格式、文件数、manifest/part ID、hash与下载URL怎样校验 | 所选版本官方文件合同及允许来源；形成下载校验矩阵 | V3单文件不证明V1 multipart已实现 |
| CE09 | 限流、Retry-After、典型完成时间及过期是什么 | 官方配额与指南；运行预算另列本地策略；记录时效和未知值 | 不把候选预算或测试耗时写成官方SLA |
| CE10 | 迁移后口径能否延续历史 | CE03–CE06映射、重叠窗口对账设计、缺字段/不同归因处置 | 字段同名不证明同口径；未知历史不自动补证 |

每条证据保存：证据ID → 文档URL/章节 → 核验时间 → 适用版本/区域/报告 → 摘要 → 支持/不支持的决定 → fixture/测试引用 → 未决项。保存公开说明的必要摘要，避免整站镜像；不将真实响应或密钥粘贴进文档。

推荐核验顺序为CE01/CE02先判路径可行，再核CE03–CE06，最后CE07–CE10。官方指南与schema冲突时标“存在冲突”，保留两侧来源，不凭经验选较宽权限/字段。目标账号证据只能在U2获批后取得，T02可完成公共合同决策而将账号可用性保持未验证。

### ADR完成与停止规则

正式版本选择必须满足身份、最小字段、日期口径、文件完整性、未知create处理均可解释；无法证明全窗口语义时可明确只支持“观察事实”而禁止完整覆盖声明。不能为赶进度补造保证。版本决定、账号权限、运行配置、真实启动是四个独立结论。

- 若选择V1：说明最小实现范围、与现有V3离线parser分离方式、历史可比性和新增测试；不能声称已完成transport。
- 若选择V3过渡：先重新确认生命周期；列迁移完成/验证/停止新采集的里程碑及剩余时间风险，具体日期须基于核实证据和实施估算，不在本模板虚构。
- 若暂缓正式接入：可将ADR标为“接受暂缓”，但T02的正式合同验收仍不得勾选；写明待补CE项、下一可行动作及不受阻的离线任务。
- ADR通过不授予真实请求权限。CE证据变化或API退役通知出现时复审；不自动切换版本、字段或账号。

## T03 不可变运行范围与最小模型提案

| 内容 | 当前承载 | 缺口与候选方案 |
| --- | --- | --- |
| 组织/工作区/Profile | Task/Request/Version/Fact 现有字段及复合关系 | 继续复用，不建第二套租户范围 |
| 计划revision | Task.planRevision，Plan.revision | 复用并在操作与提交复核；revision 不能代替冻结身份 |
| 授权身份 | 当前 Profile.authorizationId，Plan.authorizationRevision | 当前离线 scopeDigest 已涵盖授权ID/revision与绑定；正式任务创建前冻结的 manifest 仍需设计，不从可变 Profile 回推 |
| 请求日期/合同 | Task/Request日期，Request版本/类型/requestOptions | 可用 requestOptions 承载明确版本的 manifest；任务开始前创建并校验，不允许worker补写更大范围 |
| 预算/恢复 | 离线 acquisition 在requestOptions；Task已有checkpoint/nextAttemptAt/fence | 正式结构/报告分别设计；任务开始前持久化、原子扣减，未知结果不退预算 |
| 报告时区/完整性 | manifest 有时区，Fact无独立时区，DomainState是可变状态 | 先评估Request/Version稳定元数据关联；需SQL筛选/索引或完整约束时再提最小字段迁移 |

候选 manifest 必须版本化，包含 identity、contract、scope、budget、deadline、approvalReference（如适用）与 digest；动态调用计数、nextPollAt、reservation 放独立可变运行状态。digest 使用规范化字段/数组策略计算，不能直接依赖 JSON 对象键顺序。它是内容绑定，不能替代服务端权限检查或审批。

旧任务没有 manifest 时不推断已获正式报告批准。旧结构任务继续既有流程；新正式报告入口对缺失/未知版本 manifest 拒绝启动。补历史身份仅能基于可信原始证据，无法证明时记UNKNOWN。JSON方案不能自动提供数据库约束，若需要唯一性、跨进程CAS或索引，必须明确新增字段理由。

实施前提交：候选类型/字段diff、读写调用方、旧数据分类、是否需要migration及其锁/容量影响、回滚与隔离测试。不在规划阶段直接修改schema或配置。

## T04 决策与验收输出

交付应回答 [数据合同](data-contract.md) DC01–DC15，尤其决定：逐键最新还是有证据的范围替换、乱序完成裁决、partial-null汇总、历史时区与缺行语义。每个决定写支持证据、反例、查询影响和回滚方式。

接口候选采用“原字段保留 + 独立质量信息”；totals重新分组/变义必须按数据合同做显式版本方案。只为新增元数据而增加一次前端请求不是默认方案；优先同一查询返回必要摘要，不加载完整Raw。
