## 状态转换与事务边界

| 阶段 | 持久化前提 | 外部操作 | 成功提交 | 崩溃后的处理 |
| --- | --- | --- | --- | --- |
| 准备 | 固定scope/合同/预算/截止与任务类型 | 无 | Request/Version和幂等引用就绪 | 同键同内容复用；不同内容拒绝 |
| 待创建 | lease/fence有效；原子扣create预算并写reservation | create一次 | 远端ID、响应证据、下一阶段 | 未知是否发出/成功均不得盲重发；进入待对账 |
| 等待远端 | 已知远端ID、nextPollAt | 到期后才poll，扣预算 | PENDING设置下一次时间；完成则保存下载描述 | replacement fence可恢复只读poll，但仍消耗原预算 |
| 下载 | 远端完成、目标/有效期/文件合同明确 | 有界download，扣预算 | 文件及元数据/hash、完整part清单 | 有确定文件/hash可复用；失败不标已验证 |
| 校验/暂存 | 完整文件集合与合同摘要一致 | 无账号API | 有界解析、行校验、暂存事实与清单摘要 | 重试复用同版本，重复行不能多计 |
| 发布 | 最新scope/权限/lease与完整性均有效 | 无 | 任务成功、版本发布和必要状态同事务 | 提交结果未知先读本地事务结果，不再造版本 |
| 待对账/失败/取消 | 保存固定原因与已发生证据 | 默认无新请求 | 明确终止或等待人工决策 | 恢复不能补预算、扩大范围或重签旧scope |

网络调用不放数据库长事务中。reservation先事务提交，网络完成后新事务校验当前phase、operation、fence、scope和预算归属，再提交结果。文件上传与数据库不原子，失败可形成孤立对象；日志必须能定位受控引用，不能自动删文件补偿。

所有阶段均有本地工作上限；不只网络调用计时。总截止在领取、执行前和提交前复查；取消/撤权后的晚响应不能推进阶段或发布。已开始的外部请求可能仍在上游完成，停止不等于撤销。

## 调度与并发不变量

1. Queue是投递机制，数据库是任务阶段和预算事实源。队列丢失后按数据库到期记录重投；消息重复不能绕过reservation/CAS。
2. 任务类型及manifest版本必须明确识别。旧结构任务仍走原processor；未知类型拒绝且不调用API；结构scheduler不得恢复或推进专属报告等待状态。
3. lease只覆盖当前有界操作，远端等待不持有lease或占worker槽。到期时间与运行阶段分别持久化；不能把等待远端记成活跃worker失联。
4. dispatchVersion标识消息代次，fenceVersion阻止旧持有者提交；jobId、数据库幂等键和reservation各自负责不同竞态，不能互相替代。
5. scheduler并发扫描必须原子领取/更新，使用现有CAS/事务锁模式；获胜者才入队。入队后更新失败、更新后入队失败两种顺序都要可恢复。
6. 并发策略分两层：单任务同阶段互斥；同Profile/报告/重叠范围限制并发或明确排序策略。发布乱序处理依赖DC06裁决，不能用发布时间代替采集新旧。
7. 计划暂停不删除任务证据。是否暂停等待、取消未发送工作或允许已验证阶段完成，需形成显式操作语义并复用现有控制API，不能靠隐藏按钮实现。

## 错误与恢复矩阵

| 情况 | 处理 | 恢复要求 |
| --- | --- | --- |
| create超时/连接中断/未知5xx | 结果未知，保留reservation | 仅使用所选合同支持的查重/状态证据；无证据则人工决定，不重发 |
| poll/download限流 | 保存安全错误码、nextAttemptAt | Retry-After/退避受剩余预算和总截止约束；不得长sleep占槽 |
| 401/403、重绑、计划revision变更 | 停止当前任务后续外部动作 | 当前用户重新审阅目标与批准范围；不自动重连或重签摘要 |
| 下载URL过期 | 停止使用旧URL | 只有合同支持刷新下载描述时才以已批准poll预算获取；禁止重新create绕过 |
| 非法host/私网地址/重定向 | 失败关闭 | 逐跳目标策略与DNS/IP连接一致性先设计；不以允许所有HTTPS解决 |
| gzip损坏/多文件缺失/未知warning | 不暂存或不发布 | 按合同裁决重试；新下载仍计预算；不跳过坏文件 |
| 解析失败/内存上限 | 保留文件证据及安全原因码 | 不自动提高上限；提交性能/容量方案 |
| DB提交冲突或lease丢失 | 旧worker不提交结果 | 新fence读取持久阶段；不得覆写新reservation或退回预算 |
| 发布事务结果未知 | 查询原任务/版本 | 同版本已发布返回幂等结果；不是新建一轮任务 |

## 必需故障注入

| ID | 注入点 | 通过标准 |
| --- | --- | --- |
| RT01 | 两个scheduler领取相同到期任务 | 一个有效阶段操作；投递重复无重复create |
| RT02 | 扣预算后、发create前进程退出 | 不保证自动重发；保守未知状态可追溯 |
| RT03 | 上游返回后、本地保存前进程退出 | create不盲重试；只读阶段可有界恢复 |
| RT04 | 入队与DB状态更新任一侧失败 | 到期扫描能恢复；无永久丢单或无限重投 |
| RT05 | 等待时长超过lease但未到poll时间 | 不被结构恢复逻辑当失联，不提前poll |
| RT06 | 旧worker下载中被取消或换fence | 文件可能留待处理，但无事实发布/错误阶段提交 |
| RT07 | 另一个Profile使用相同远端reportId | 不串文件/预算/事实，复合scope保持隔离 |
| RT08 | 重复STAGE/PUBLISH及提交响应丢失 | 同版本同事实不重复；成功状态与发布原子 |
| RT09 | 总截止到达、剩余调用仍有额度 | 停止新调用与推进；不因额度未用尽延长 |
| RT10 | 网络响应/解压流持续发送小块 | 总字节/时间上限仍有效；连接/reader可靠关闭 |
