## 目标与基线

业务目标：运营人员与 AI 能从同一份可追溯广告事实定位问题，形成可审阅草稿；获批后通过已验证渠道执行并回读结果。

当前已完成八类 SP 结构读取基础及 Campaign 日报离线采集/发布/页面/MCP 切片。尚无常规报告 worker 接线、真实报告验收或正式广告写 transport。不得把离线完成记为全域接通。

本轮仅补规划文件。沿现有 Spec Kit 的 spec → plan → tasks 建立追踪，不运行带 implementation 阶段的自动工作流，不修改分支、配置或既有工作流状态。

## 用户路径与验收场景

| 路径 | 用户需要 | 验收证据 |
| --- | --- | --- |
| US1 同步与诊断 | 查看某 Profile/报告/日期范围的进度、失败与可恢复位置 | 实际队列 fixture 从提交至发布；worker 中断后恢复；失败不改变最后成功版本 |
| US2 可信分析 | 在 Campaign 页面和 MCP 查询相同范围 | 对象 ID、总量、汇总、指标口径、来源版本一致；空/null/未覆盖可区分 |
| US3 真实只读试点 | 对一个指定 Profile 做有限读取 | 独立目标审批单、真实响应抽样对账、预算及停止记录；真实验收前保持未验证 |
| US4 可审阅优化 | 根据成熟数据形成逐项草稿 | before/after、规则和事实版本、关联结构、风险、revision 均可追溯；AI 不直接执行 |
| US5 受控执行 | 批准后应用并确认远端结果 | 审批内容与执行摘要一致；未知结果进入对账；Bulk 导出与 Amazon 已应用明确分开 |

## 需求约束

- FR01：能力状态分别表达官方合同、代码实现、离线验证、账号授权、真实验收、UI/MCP 接线；不得用一个“支持”布尔值替代。当前 `capabilities.ts` 的报告采集描述需后续更新，新增离线状态不扩大正式权限。
- FR02：正式报告版本必须经过决策记录，包含端点、账号身份、区域/请求头、字段/归因、历史限制、空行/缺行/warnings、文件与下载合同。V3 停用日期按已有公共文档证据记录；正式实施前重新核对，不预设 V1 与 Profile 的等价映射。
- FR03：运行范围、报告类型/版本、日期、预算和截止必须在任务创建时固定并与审批范围绑定。不得通过修改计划扩大在途任务；旧结构 checkpoint 保持兼容。
- FR04：排队、运行 lease 与远端等待分开处理；等待时释放 worker，按到期时间重新调度。重启、多进程和重复消息不能重复创建或发布。
- FR05：Raw 文件、标准化事实与查询派生职责分开；字节、哈希、来源、合同版本均可验证。敏感原始正文和签名 URL 不进入普通页面/MCP/日志。
- FR06：明确覆盖语义后才能处理零行或缺失实体；“没有返回”不能自动归零/删除。发布完整性、同步新鲜度、归因成熟度三项分别表达。
- FR07：同口径指标至少区分广告产品、API/报告合同、币种、归因窗口、报告时区及日期语义。比率从同组总量计算，分母零/null 保持不可计算；不平均行级 ACOS。
- FR08：绑定、授权、成员/凭证权限与计划 revision 在请求前及提交/返回前复核；组织、工作区、店铺、Marketplace、Profile 交集以服务端为准。
- FR09：建议绑定稳定远端对象 ID、结构观察与事实版本；证据过期、关联歧义、归因未成熟、权限变化时阻止生成可执行变更。可返回只读诊断与缺口。
- FR10：每项新数据域同时交付合同、存储、查询、页面、MCP 和质量证据。Product Ad 对象与 Advertised Product 报表、Search Term 与 Keyword ID 分开建模。

## 数据风险与处理原则

| 风险 | 影响与历史数据 | 回滚/补偿与并发要求 |
| --- | --- | --- |
| P0 隔离失效或未知结果重复写 | 越权读取、重复广告变更；可能影响真实支出 | 禁止真实启用；保留审计，对账后人工补偿；每次执行使用独立幂等及 fence |
| P1 覆盖/时区错误造成错误建议 | 旧行继续被选中、不同日期口径混合；影响历史解释 | 保留旧事实与读路径；修正规则后重建派生数据；无证据不推断缺失 |
| P1 任务恢复或文件完整性不足 | 重复请求、部分文件发布、worker 资源耗尽 | 新报告入口可停用；保留任务和原始对象；不删除历史以修复状态 |
| P2 能力清单/页面状态落后 | 误以为正式可用 | 更新状态及证据链接；不改变真实权限或自动启动同步 |

以上是设计风险分级，不表示本次发现真实数据损坏。当前未访问真实数据库，历史影响需在获批目标范围内另行核验。

## 成功标准与非目标

阶段性成功以可复现证据判定：离线队列闭环 → 一个 Profile 真实只读试点 → 一个 SP 优化场景草稿 → 一个已验证操作执行闭环。各阶段独立验收，不能用测试数量替代账号验收。

暂不扩 DSP、不引入新数据库/搜索服务/缓存，不改 Product Center 事实源，不承诺 Amazon 未开放能力，不进行无限历史同步或自动广告写入。新增共享模型、权限/API 契约、worker、配置及性能影响先给具体方案再实施。
