## U1-B/C：文件与任务设计

运行状态为设计目标，非现有枚举承诺：待提交 → 创建中 → 等待远端 → 下载 → 校验/暂存 → 发布 → 完成；旁路为限流待重试、待对账、失败、取消。阶段尽量用现有 Request/Task/Attempt 记录，不为每个状态新建系统。

- 创建前提交 reservation 与持久预算；create 结果未知停止重发，仅在所选 API 提供可验证的查重/状态能力时恢复，否则人工处理。
- 远端等待按 `nextPollAt` 调度，worker 不持有长时间 sleep。lease 只覆盖当前操作，超过 lease 的进程不能提交；任务总截止与单次操作 timeout 分离。
- 预算包含 token refresh、create、poll、download、重试及字节数；429/5xx 仅按合同与 Retry-After 处理且不突破总截止；401/403、重绑、撤权、未知响应立即停。
- 存储上传与数据库事务间可能产生孤立文件：文件先不可消费，元数据/hash 完成再发布引用；孤立对象只记录待处理。保留期/清理脚本另审，不在普通同步中删除历史。
- 正式下载策略需核对可信 host、DNS/IP、私网/metadata 地址、重定向每一跳、签名有效期；不把 `*.invalid` 规则机械改成任意 HTTPS。
- 读取 storage 对象也执行流式字节上限，防止元数据小而实际文件大；解压总量、行数、超时和并发分别有界。Raw 保存原始响应字节与解析结果的映射，失败响应按敏感级别加密/摘要处理。

数据质量结果至少区分：未同步、运行中、失败、观察到已发布数据、已验证范围完成、合同确认的空结果。新鲜度与归因成熟度作为独立维度；默认只读查询可返回带限制的数据，生成可执行草稿时按策略阻断。质量中心先放既有已同步数据/任务详情，不新铺一级导航。

## 性能、存储和验证预算

下表为**待实施时确认的候选验收门槛**，不称现有结果，也不直接写入生产配置：

| 项目 | 隔离实验方案 | 候选通过条件 |
| --- | --- | --- |
| 查询 | 相同硬件/种子/权限下 1万、10万、100万事实；1/5 Profile；10/50 并发，分别记冷/热结果 | 页查询含 totals 的 P95 ≤ 2 秒、P99 ≤ 5 秒；不满足时记录 SQL/索引证据后决策，不先加缓存 |
| 兼容回归 | 改动前后相同数据与负载对照 | 原结构查询 P95 增幅 ≤ 10%；抽样结果/分页/权限一致 |
| 文件处理 | 按候选压缩上限 B、解压上限 U 测极限及超限文件；先用隔离小上限 | 记录单任务峰值 RSS、CPU、耗时；超限即停，下载缓冲不随完整文件无限增长 |
| worker | 重复 dispatch、限流、进程终止、lease 到期、取消与发布竞态 | 不重复创建/发布；无长等待占槽；每次调用可追溯预算 |
| 存储 | 记录每 Profile 每日压缩文件/证据/事实/索引大小与修订频率 | 给出 `Profile数 × 日增量 × 保留天数 × 修订系数 + 索引/备份` 的容量估算，再评审保留期 |

B/U、并发、回补天数、运行截止和存储保留期待真实样本与合同确认，不沿用离线 1MiB/8MiB/1000行/15分钟作为生产标准。出现明显资源/P95 影响时，先报告范围、替代方案与回滚，再获批改动。
