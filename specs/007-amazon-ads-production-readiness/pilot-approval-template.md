## 3. 命令与数据写入边界

精确命令：待实现和审核后填写；当前没有可执行命令，不虚构CLI参数。每个命令标明cwd、版本、配置引用、预检查、预期输出及影响。不要用“运行最新脚本”代替命令。实际命令与审批版本不一致即停止。

写入范围：逐表列出计划/Task/Attempt/Request/Document/Version/Fact/Entity/DomainState/FileObject/Audit涉及项；未用到的表明确“不涉及”。列storage provider与对象前缀、Redis队列命名空间、隔离库身份摘要；严禁跨旧/新服务器数据集误用。

为已有数据制定冲突策略：是否创建新版本、是否更新当前结构、是否允许影响普通页面。不得清空旧表、覆盖原始对象或推断缺席为删除。权限与数据库故障时保留已提交证据，不为了恢复而清库。

## 4. 预算与停止条件

| 预算 | 本次批准值 |
| --- | --- |
| token刷新、结构请求/页数 | 待填写，失败重试仍计入 |
| report create/poll/download | 待填写，逐项上限和总请求上限 |
| 文件数量/压缩/解压/行数 | 待填写，含失败响应字节限制 |
| 并发/运行截止/单次超时 | 待填写，停止时不得再启动下一操作 |
| DB与storage增长 | 待填写候选上限/监测方式；空间不足停止，不自动删除 |

401/403、身份/区域不匹配、撤权/重绑、合同未知、无完整文件证据、预算/截止超限、配置漂移、存储或数据库异常均停止。429/5xx是否重试以审批中的合同策略为准；未知create结果进入待对账，不重新创建。

## 5. 暂停、恢复、回滚

暂停命令：待填写且先用mock验证。说明已发出请求可能继续在上游完成，取消本地任务不能声称撤销上游请求；返回数据仍需fence检查，不能发布到已取消任务。

恢复条件：明确使用原任务还是新任务、已用预算是否延续、未知创建如何对账、授权与digest如何复核。延期/扩窗/换环境/换Profile/增加预算均重新提交范围，不沿用旧批准。

回滚：停用新入口、恢复应用/批准涉及的配置，保留已保存文件和历史事实；不自动回滚数据库、不撤销真实数据或清理孤立对象。部署存在时按AGENTS.md的CI artifact链路独立执行。

## 6. 验收与批准记录

验收至少包括：上游报告ID/采集时间的脱敏引用、请求/文件hash与数量、行数、同口径抽样、数据库/UI/MCP一致性、空与覆盖说明、权限负例、总预算消耗、失败/未决项。对账按相同时间、时区、币种、归因、过滤条件，来源滞后不能擅自当成精度误差；抽样容差必须事先定义。

批准记录：待用户针对本单的环境、revision/digest、分项操作、预算、有效期明确批准后填写。不把“继续完善规划”“开始编写代码”记录为本单批准。执行结果与批准分别记录；批准后仍需预检查，不满足时停止。
