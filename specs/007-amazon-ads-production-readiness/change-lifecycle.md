# 统一草稿、审批、执行与对账设计

日期：2026-11-06。状态：U4/U5待评审设计。对应T20–T22；下文状态为目标语义，不表示现有数据库枚举已实现。

## 已有边界与复用

代码证据：`agent-platform/amazon-action-audit.ts`已持久化预览、AgentApproval、执行记录及审计；`amazon-action-policy.ts`已有digest、幂等与竞价预览校验；`amazon/ads-client.ts`有请求/逐项响应合同基础，但默认client抛NOT_IMPLEMENTED。当前预览明确说明旧值来自提交报告、rowId不等于Amazon entity ID。

因此先增强统一服务的稳定对象映射、服务端证据引用和执行对账，不另建审批事实源。现有数值范围和30分钟预览有效期是实现现状，不能当各站点正式竞价规则或未来统一SLA；正式合同逐项确认。API transport阻断继续保留，环境开关不能独自授权或实现执行。

## 草稿最小内容

| 内容 | 设计要求 |
| --- | --- |
| 身份 | organization/workspace、Seller/Marketplace、内部/Amazon Profile、authorization ID/revision、region |
| 对象 | 官方稳定entity ID、类型、Campaign/AdGroup归属、操作类型与作用层级；不使用显示名称/Excel行号代替 |
| 变更 | 类型化before/after、币种/单位、精度、站点限制；不接受任意透传payload |
| 证据 | fact/version IDs、范围/口径digest、历史结构观察、质量和成熟策略、规则版本、理由与风险 |
| 生命周期 | 创建者、来源UI/MCP/Skill、revision/digest、创建/过期时间、审批引用、逐项接受/拒绝 |
| 执行 | 渠道、批次与单项幂等标识、attempt/fence、已发送证据、响应摘要、回读与对账引用 |

事实引用在服务端重新查权限/状态，不相信客户端传来的指标、质量标签或before值；旧Bulk工作流继续兼容，但未经远端对象核验的草稿不能升级为正式API操作。

## 状态与允许动作

| 状态语义 | 可做什么 | 离开条件 |
| --- | --- | --- |
| 编辑中 | 改选项、重新分析、保存草稿 | 服务端校验后形成审阅版本 |
| 待审阅/待审批 | 审阅证据、逐项接受拒绝 | 接受集合与payload固定；决定绑定revision/digest |
| 已批准待执行 | 查询、撤销未发送项、申请独立执行 | 权限、审批范围/有效期、现值及合同再校验 |
| 执行中 | 观察进度，停止尚未发送项 | 每项转远端接受/拒绝/结果未知；不使用整批笼统成功 |
| 待回读/待对账 | 按预算只读核验 | 证据足以确认目标值、拒绝、冲突或仍未知 |
| 已验证生效 | 查看审计、提出逆向草稿 | 不修改原审批或历史结果 |
| 已拒绝/过期/冲突/取消 | 查看原因、基于新证据创建新revision | 不能复用旧批准继续发送 |

审批后改变值、对象、渠道、选中集合或范围时，新revision重新审批；记录原批准失效原因。证据出现新修订时先判断其对原理由是否有影响，不能自动假设仍适用；执行前做明确政策复核。已发送请求不能因“取消”声称上游已撤销。

## 执行前与并发控制

- 先核准单一操作和合同，再扩其他操作；UI与MCP走同一执行服务。分析/建草稿/审批/执行权限分别判断，审批不自动调用transport。
- 执行前只读获取远端现值及归属。已不同于before则记录冲突，不覆盖。若上游无CAS，必须说明“现值检查与写入间仍可能变化”的限制；本地对象锁/fence不能阻止Amazon控制台或其他系统同时操作。
- 同组织/Profile/对象/字段进行服务端冲突控制；冲突规则跨UI/MCP/Bulk统一，具体锁和数据库约束先评审。操作与提交复查scope，锁持有不跨长时间等待。
- 幂等标识绑定revision/digest/渠道/单项。任何超时、5xx或缺项响应均不能证明未写入，不自动重发；保留已知成功项并对未知项单独对账。
- 写请求接受不等于回读验证。已有parser中的APPLIED仅表示响应解析标签，未来界面应映射“上游报告接受，待回读”，不能直接显示最终生效。

## API 与 Bulk 渠道统一口径

| 渠道 | 成功到哪一步 | 未完成部分 |
| --- | --- | --- |
| API | 收到完整逐项接受证据 | 按合同延迟/预算回读确认；未知或冲突保留，不笼统成功 |
| Bulk导出 | 生成包含已选已审项的有效文件和manifest/hash | 未上传、未被Amazon接受、未回读，不记生效 |
| Bulk结果导入 | 通过scope、源文件hash、对象、操作、索引/结果映射核验 | 无法绑定的行隔离审阅；上传结果证据与远端验证区分 |

同一草稿不能在API发送结果未知时改用Bulk重做。Bulk文件可能在导出后由外部修改或晚上传，ERP不能保证文件被外部应用时仍获有效批准；UI需明确边界。结果不一致时标外部变更/待对账，不篡改原草稿以匹配结果。

逆向操作生成新草稿，基于当前远端值、当前权限和新审批执行；不自动恢复历史竞价、预算或数据库快照。广告支出不可逆，代码回滚不等于广告状态恢复。

## 故障与验收案例

| ID | 场景 | 预期 |
| --- | --- | --- |
| CL01 | 批次5项：2接受、2拒绝、1缺失 | 2待回读、2失败、1待对账；不得把5项全成功或全重试 |
| CL02 | 远端写入后进程在保存结果前退出 | reservation/发送证据保留，重启对账，不直接重发 |
| CL03 | 审批后before已被人工改动 | 冲突停止，生成新revision重新审阅 |
| CL04 | 执行中撤权或重绑 | 未发送项停止；已发送项保留未知/接受状态，不用旧授权继续回读；由当前获批权限另行对账 |
| CL05 | 一次按钮点击与MCP并发请求 | 同幂等内容返回同执行；不同内容同键拒绝；对象冲突明确 |
| CL06 | 回读超时或读到旧值 | 按有界策略继续只读验证；截止后待对账，不自动认定失败并重写 |
| CL07 | 逆向草稿遇到当前值不等于原after | 再次冲突，不覆盖其他操作者新变更 |
| CL08 | Bulk导出成功，用户未上传 | 状态保持已导出，报表不计为已应用 |

进入U5前需补真实逐操作合同、当前权限调用方盘点、最小schema/API差异、性能与故障注入方案，并单独审阅。同步中心的owner/database_admin自行审批规则不自动扩展到广告变更。
