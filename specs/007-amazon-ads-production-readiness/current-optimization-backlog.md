## 三、U2正式同步Worker待办

| 项目 | 设计要求与验收 |
| --- | --- |
| 定时、初始化、历史回补 | 复用任务创建服务，显式taskKind/dataDomain/reportType/contract/dateRange；定时增量按已核时区和归因策略计算，初始化不能隐式变成全历史 |
| 回补拆窗 | 按所选报告最大窗口切分，父请求保存子窗口计划/进度；持久游标指向已确认阶段。仅示例拆窗逻辑，不预设全部API为31天 |
| 优先级 | 候选顺序：恢复必要只读操作→手动小范围→到期增量→历史回补；设等待老化/份额避免回补饿死。优先级不能绕过权限或预算，具体权重压测后确认 |
| 并发控制 | 同任务同操作互斥；限制Profile/授权/区域及全局资源并发；重叠窗口串行或明确定序，租户公平；具体额度为待评审配置，不冒充官方配额 |
| API限流 | 按合同识别限流作用域，跨worker协调；429有界退避并受Retry-After/截止约束；仅进程内计数不足以证明多worker限流 |
| 超时与重试 | 区分单请求、阶段、本地解析和任务总截止；不重置累计预算。create结果未知不重发；poll/download仅在证据和合同允许时重试 |
| 暂停/恢复/取消 | 暂停停止领取新步骤并保留阶段；取消停止剩余操作并fence晚响应；恢复使用原范围和剩余预算，不能自动恢复过期批准或变更绑定 |
| 崩溃恢复与去重 | DB阶段/reservation/预算为事实源，队列可重投；固定幂等键绑定范围/内容；重复消息和两个worker不重复create/发布 |
| 进度持久化 | 区分请求/文件/解析行/窗口完成量；预计总量未知时显示已处理量和阶段，不伪造百分比；失败重试保留Attempt历史 |
| 调度兼容 | 现有结构scheduler会扫描RUNNING过期任务并写entities状态，接线前必须限定任务类型，不能误接管报告等待或写错DomainState |
| 事务发布 | create/poll/download/校验/staging/质量/发布独立可恢复；文件完整、权限scope/fence复核后同事务发布版本及任务结果，失败不产生伪成功 |

目标流程：创建任务 → 校验Profile/实时权限/域与合同 → reservation及create → 轮询等待 → 按实际合同获取单文件或全部分片 → 保存Raw → 有界解析校验 → staging →质量检查 → 原子发布。成功的create不能因worker重启再次创建。

父回补请求完成需所有子窗口有明确结果；部分完成、合同确认空、失败/未知分别呈现。若涉及新增父子关系或索引，先提交schema/兼容diff，不默认加表。调度内存、下载/解压CPU、索引和存储增长须以T14候选规模验证；先小窗口/低并发，未证明收益不加Redis业务缓存或新数仓。

## 五、报告日期与时区硬约束

拟在不可变Request/Version合同元数据保存`reportTimezone`、`dateSemantics`、来源证据及合同版本；名称和具体落点需模型评审。Fact按所属发布版本追溯，若为SQL性能去规范化字段，验证写入一致性和索引成本，不能制造第二事实源。

原始`YYYY-MM-DD`保存为报告当地日历标签，采集/生成/发布时间保存绝对时间；明确点击日/转化日/其他语义。仅可从当次权威响应或已核合同/账号设置证据固定时区。无证据记UNKNOWN；禁止使用Profile当前时区回填或推断历史。时区变更产生新合同/观察，不静默重解释旧日；DST边界专项验证。

跨时区/归因/日期语义数据默认分组；不存在精确时间粒度证据时不强行转换日报为同一UTC窗口。partial-null保持指标完整性限制，不用SUM忽略null的已知小计伪装全量总计。

每条建议引用事实版本/对象观察、口径、规则版本、理由、限制和生成时间。异常先检查数据质量；证据不足只给诊断。MCP只创建草稿，不绕过统一审批；工具目录出现不等于凭证已授权。实际tool ID、schema和权限diff实施前列明，不在规划里冒充工具已注册。

## 七、U5真实验收与执行顺序

| 顺序 | 验收对象 | 必需证据与限制 |
| --- | --- | --- |
| 1 | OAuth | 目标环境授权身份、过期/撤权/重连行为；验证已存在有效授权时不自动重连 |
| 2 | Profile发现 | 真实范围与region/站点/币种/时区，独立请求预算；不因登录成功认定报告权限 |
| 3 | 店铺绑定 | 内部/外部ID与组织归属一致；绑定写入单独批准 |
| 4 | Campaign真实读取 | 上游来源与本地对象对账；现有结构任务会跑八类，须明确批准全范围或先做限定域能力 |
| 5 | Report创建/下载 | 正式合同、小日期窗、远端ID、全部文件与哈希、预算消耗 |
| 6 | 本地落库 | 目标库身份、任务/Raw/Request/Version/Fact引用、已发布状态；不能以mock数据代替 |
| 7 | ERP查询 | 相同Profile/日期/口径、行/总量/指标、空与质量状态 |
| 8 | MCP查询 | 同一查询结果、scope负例、过期及撤权阻断 |
| 9 | 历史回补与增量 | 重叠日期修订不重复累计、恢复不重建成功报告、时区及日期边界正确 |
| 10 | 单一广告写操作 | 在只读及草稿验收后另批准，校验现值/审批digest、逐项执行、回读和未知结果对账 |

以上是验收顺序，不要求对有效既有授权重新执行每次OAuth/发现；每项先记录“已有可信证据/需新操作/未验证”。授权、发现、绑定、配置应用、真实任务启动及广告写入均按具体范围分别批准。审批通过不自动启动下一步；目标变化重新提交。
